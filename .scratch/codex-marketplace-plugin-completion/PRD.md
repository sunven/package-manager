# Codex 市场与插件管理补全

Status: ready-for-agent

日期：2026-10-15。通过 `grill-with-docs` 完成三轮、九项范围与行为确认，用户已确认整体方案。已完成实施、自动化验证与独立界面审阅；结果和覆盖边界见[验证记录](VERIFICATION.md)。

配套文档：[事实核查](RESEARCH.md)、[ADR-0014](../../docs/adr/0014-plugin-lifecycle-uses-cli-and-details-use-readable-local-files.md)、[领域术语](../../CONTEXT.md)。

## 目标

在现有 Codex 插件市场管理能力上，完成使用者浏览、查看详情、安装、启停、市场同步、重新安装和卸载插件的管理闭环。

## 已确认范围

第一轮，用户逐项确认：

1. 面向插件使用者完成管理闭环。本轮不加入插件或市场的制作、编辑、打包与发布流程。
2. 管理本机 Codex 发现或配置的市场。本轮不接入公共插件目录、工作区插件或组织发布能力。
3. 继续管理当前 Codex home 的用户默认设置。本轮不增加指定项目的配置管理或项目覆盖编辑。

第二轮，用户逐项确认：

4. 沿用市场分组，展开市场后浏览插件，增加市场内搜索及「全部／已安装／未安装」筛选和插件详情。沿用现有视觉系统，不新增独立插件库页面。
5. 插件详情展示简介、作者、来源、版本、安装策略与技能／MCP 服务／Hooks 的只读能力清单。Hooks 可跳转现有管理页；本轮不新增技能编辑、MCP 服务启停、连接认证或工具权限管理。
6. 安装、卸载、启停采用单项操作，逐次说明目标与影响。本轮不做批量选择。
7. 补齐市场添加的分支／标签、稀疏检出及 `.claude-plugin/marketplace.json` 兼容布局。Git 参数放入可展开的高级选项，保留简洁的常规添加流程。

第三轮，用户逐项确认：

8. 区分「同步市场」与单插件「重新安装」。前者遵循官方市场同步范围，可能影响多个已配置插件；后者明确会将插件启用，不包装为保留禁用状态的更新，也不承诺取得上游最新版。
9. 按实际可读信息展示详情。尚未下载的 Git/npm 插件先显示清单与目录提供的信息；本地文件可读时补充完整详情，无法取得的信息明确说明。不为预览自动安装，不新增远程源码下载器。

## 已有能力与本次扩展

- 已有市场源添加、逐个刷新、移除，以及按市场组织的已安装插件清单和用户默认启停。
- 本次新增市场目录中的未安装插件、插件详情及单项安装／重新安装／卸载操作，并补齐市场源高级选项。
- 市场目录项与已安装插件分别建模；市场可发现、已安装、用户默认启用和会话已加载不可互相推断。术语见根目录 `CONTEXT.md`。
- 旧迭代不提供独立安装／更新／卸载的范围限制，在本次重新打开；这不推翻 ADR-0012 关于市场刷新可能连带同步已配置插件的结论。
- ADR-0011 的官方清单、用户级启停边界，以及 ADR-0013 的原生 hooks 清单和信任管理边界，作为现有设计依据；若后续决定改变，需明确记录。

## 交互约定

- 市场行仍是插件浏览入口。无已安装插件的市场也可浏览目录；市场中同名插件沿用所属市场区分身份。
- 插件列表区分安装状态与用户默认启用设置。未安装项提供安装入口；已安装项提供现有启停及新增重新安装／卸载入口。Git 市场提供同步入口，本地市场不显示无法执行的 Git 同步操作。
- 插件详情沿用现有组件与主题，集中展示插件身份、元数据、来源与只读能力；技术路径保留用于复核。未获取到的信息不填造默认值。
- 保留现有独立的 Hooks 页面及其信任边界。插件详情中的能力声明不等于原生运行时已经加载的 Hooks 清单。
- 市场源移除与插件卸载保持独立操作；新增生命周期能力不将旧有移除市场操作变成批量卸载。
- 沿用确认、执行前复核与操作后重新读取流程。命令失败和命令成功后重读失败分别反馈，不将过期数据呈现为最新事实。

## 数据与执行规则

- 安装事实和市场目录继续来自官方 CLI；安装／重新安装／卸载分别委托 `plugin add`／`plugin add`／`plugin remove`，市场同步委托原有 `marketplace upgrade`。本应用不自行复制或删除插件缓存以模拟生命周期。
- 清单使用包含未安装项的官方读取能力；目录项按市场与插件身份同已安装清单关联，不能通过缓存是否存在推断安装。
- 详情可以补读已安装副本和可访问本地来源的 manifest 与组件声明。遵守 portable 根 manifest、`extensions.com.openai` 与兼容 overlay 的选择规则，不混合两个 OpenAI overlay；不执行组件脚本或建立 MCP 连接来生成详情。
- 官方 `plugin/read` 等接口仍标注不宜用于生产客户端，本次不依赖这些接口取得详情；稳定 CLI 不能提供的内容不伪造。
- 来源版本选择器与实际安装版本分别展示；未知版本或来源未变化时不制造「可更新」标记。安装事实以 CLI 清单为准。详情优先读取 CLI 提供的安装路径；未提供路径时可结合实际版本和文档中的缓存布局定位可读元数据，但不据此推断安装状态。
- 依据安装策略解释资格；`NOT_AVAILABLE` 可展示但不能提供可执行的安装入口。后端操作前重读并交由 CLI 最终校验，不绕过托管策略。
- 安装或重新安装将插件启用，确认内容明确这一结果；不自动补偿成原禁用值。`ON_INSTALL` 等认证策略只描述要求，安装成功不等于服务认证或连接完成；认证仍由 Codex 完成。
- 卸载使用原生命令，并说明将移除插件安装及其配置。不得承诺清理了凭据、插件数据或 Hooks 信任记录，也不追加对这些对象或原始来源目录的删除。
- CLI 不存在、不兼容、读取失败与清单为空分别表达；新增命令不可用时解释限制，不以直接改缓存或实验接口绕过。
- 沿用当前用户 home、结构化参数、目标复核和配置冲突处理，保留无关设置。市场源维护资格与插件维护资格分别判定。

## 验收场景

1. 市场只有未安装插件时仍能展开、搜索并安装；筛选正确区分全部、已安装与未安装。
2. 同名插件来自不同市场时，详情与写操作始终指向选定市场中的插件。
3. 插件详情展示实际可读的元数据与组成，不混淆目录声明、安装状态、用户启用选择和会话加载状态。
4. 单项安装、卸载与启停在确认后执行，结果反映后端重读的真实状态；陈旧目标或资格变化不会静默写入。
5. Git 来源支持指定 ref 与多个 sparse 路径；本地来源兼容官方说明的两种市场布局；不接受不适用于本地来源的 Git 参数。
6. 默认、托管和归属不明的市场保留现有维护边界；目录或详情读取失败不消除仍可展示的已安装插件信息。
7. 插件整体维护后 Hooks 清单失效并按现有规则重读；不自动授予信任或修改单个 MCP 服务策略。
8. 长名称、长来源地址、空目录、无搜索结果、加载与读取错误在现有桌面布局、窄窗口及明暗主题下可操作。
9. 重新安装已禁用插件时，确认前明确会启用；执行后以官方清单和用户设置展示结果。同步市场不能标为只更新目录，也不能承诺仅影响选定插件。
10. 远程未下载插件的详情不完整时仍可浏览基础信息，不显示虚构的空组件清单；本地可读后展示真实详情。详情解析失败不抹掉已确认的安装事实。
11. `NOT_AVAILABLE` 安装被阻止；认证策略不会被当作认证完成状态；命令成功、已保存状态与当前会话是否生效保持区分。
12. 卸载后重读确认安装清单；不因重复卸载返回成功而报告虚构的删除数量或回收空间。

## 实施顺序与验证

1. 扩展官方清单适配、目录关联及详情读取：用目录／安装状态不一致、缺失元数据、portable 与兼容 manifest 的 fixture 验证。
2. 接入单项生命周期及市场源高级参数：验证执行前复核、策略拒绝、CLI 失败、操作成功但重读失败与作用域边界。
3. 扩展现有市场列表、筛选与详情交互：验证安装、重新安装、启停、卸载及 Hooks 导航；保留已有市场与插件错误隔离。
4. 运行相关 Rust／前端检查及有边界的浏览器验证，并在专用临时 Codex 环境复核受支持原生命令。原生 Tauri 端到端和未覆盖来源／版本须在验证记录中如实说明。
