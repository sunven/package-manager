# VS Code 工作区存储占用

状态：已实现并验证。

## 目标

让用户看清 VS Code 为哪些工作区保留了数据，以及各工作区存储的目录占用。首版只读展示，不提供清理或删除操作。

术语以 [CONTEXT.md](../../CONTEXT.md) 中的「工作区存储」「目录占用」「VS Code 占用」为准。

## 已确认的需求

- 新增独立的「VS Code 占用」入口。
- 只观察 `workspaceStorage`，不扫描项目源码目录，也不纳入 VS Code 的其他数据目录。
- 每个工作区存储目录一行；同一项目关联多个存储目录时分别列出，不按项目合并。
- 展示项目或工作区名称、项目位置和目录占用，并保留存储目录的身份以区分重复项目记录。
- 对应本地路径不存在时标注「路径不存在」；缺少或无法解析项目映射时标注「未识别工作区」。两类记录均保留，并计入占用汇总。
- 清单表示仍留有工作区存储的记录，不承诺覆盖完整打开历史，也不表示当前打开的窗口。
- 首版没有删除按钮、批量选择或清理执行能力。

## 已确认的默认行为

- 首版面向 macOS 当前用户的 VS Code 稳定版默认目录：`~/Library/Application Support/Code/User/workspaceStorage`；暂不增加自选目录、Insiders 或其他编辑器入口。
- 首次进入页面时扫描，之后通过「刷新」手动重扫；切换页面保留本次结果，不定时刷新。
- 默认按占用从大到小排序，可按项目名称或路径搜索。
- 每行展示名称、项目路径或工作区 URI、存储目录、占用和识别状态；多文件夹工作区以工作区配置位置标识。
- 页面独立汇总工作区存储数量和占用，不加入现有包管理器的占用合计。
- 大小沿用应用现有的磁盘占用口径，不展示「可释放空间」或未经证实的「最近打开时间」。

## 识别与异常展示

- 同时识别元数据中的文件夹映射与工作区映射；不能只根据 `.code-workspace` 扩展名判断工作区。
- 没有可用项目名称时，用存储目录标识区分记录。存储目录名不限定为十六进制或固定长度。
- 远程工作区若有本机存储，展示其 URI 并统计本机目录占用，不尝试连接远程位置。
- 源目录不存在时显示未发现工作区存储；无法读取源目录时显示读取失败，不能伪装成空清单。
- 单项读取或测量失败时保留该记录并显示原因，其余记录继续展示。汇总明确标注统计不完整，不把未知占用当作零。

## 验收标准

- 本地文件夹和多文件夹工作区均能显示关联位置，含空格或中文的文件 URI 能正确呈现。
- 同一项目对应多个存储目录时，行数与存储目录数一致，各行保留独立占用。
- 路径不存在、缺少或损坏项目映射的记录仍在清单及汇总范围内。
- 刷新能够反映新增、移除或大小变化的存储目录；扫描期间界面保持可操作。
- 部分读取失败不隐藏其他记录，也不生成虚假的完整合计。
- 页面及新增后端接口均只提供观察能力；现有管理器维护和项目清理行为不受影响。
