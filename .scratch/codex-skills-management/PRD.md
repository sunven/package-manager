# Codex 技能管理

状态：已实现；自动化与隔离真实 CLI 验证通过，界面终审记录见 [VERIFICATION.md](VERIFICATION.md)。

## 目标与范围

在包管理器控制中心的 Codex 页面新增「Skills」页签，完成技能的查看、搜索、启停、安装、更新和卸载。范围限定当前用户，沿用当前环境的一份 Codex home，不增加项目选择器或项目技能管理。

首版不包含技能创作或内容编辑、旧技能接管、批量维护、后台自动更新、强制覆盖或永久删除。术语见 [CONTEXT.md](../../CONTEXT.md)，接入取舍见 [ADR-0019](../../docs/adr/0019-codex-skills-use-native-discovery-and-owned-installations.md)，事实依据与实验限制见 [RESEARCH.md](RESEARCH.md)。

## 清单与维护对象

清单来自兼容 Codex CLI 的原生技能发现，在项目外上下文读取；缺失、不兼容、读取失败和空清单分别表达，不回退为目录扫描推断 Codex 已识别的技能。启停使用 Codex 原生配置接口。本应用维护独立技能的安装副本与来源记录，不引入第三方技能管理 CLI 作为生命周期依赖。

| 对象 | 查看 | Codex 启停 | 更新／卸载 |
| --- | --- | --- | --- |
| 本应用安装且身份可核实的独立技能副本 | 支持 | 支持 | 支持 |
| 原有独立技能，没有本应用安装记录 | 支持 | 支持 | 不接管 |
| 既有共享目录或外部链接提供的独立技能 | 支持 | 支持 | 回原来源维护 |
| 插件技能 | 原生发现的条目只读 | 回所属插件管理 | 回所属插件管理 |
| 内置技能及非用户范围来源 | 原生发现的条目只读 | 不提供 | 不提供 |

上述操作仍须通过原生能力、当前状态与目标身份检查。插件归属优先于 user scope：原生插件技能也可能返回 `scope: user`，不能因此开放单技能维护。

新页签以原生清单为准，不补读禁用插件的技能声明；说明已验证版本不展开这些技能，用户可在插件详情查看其声明。技能启用状态不代表运行中客户端已加载或调用；修改后按 Codex 的要求在重启或新会话中核对。

来源记录只用于追踪本应用的安装副本和维护资格。位于 Codex home、出现在原生清单或存在其他工具的锁文件，都不构成本应用的接管依据。原生未识别某个安装副本时应说明异常，不能根据来源记录伪造原生清单项。

## 安装、更新与卸载

### 安装

- 支持 GitHub 仓库及本地技能目录，单次安装一个技能。GitHub 可指定技能子目录及分支／标签。
- 新副本放入当前 Codex home 的 `skills` 目录，通常为 `~/.codex/skills`。本地导入使用复制，保留原目录，不创建持续指向来源的链接。
- 保存来源、选定的分支或固定版本、技能子目录、安装位置及完成安装时的内容基准，供更新和本地修改检查使用；不改写其他工具的来源记录。
- 新装默认启用。执行前展示技能、来源、目标位置及启用结果；安装仅获取和复制内容，不调用技能或运行其中脚本。
- 目标安装目录存在时停止，不覆盖或自动另起目录名。仅名称相同而路径不同的原生技能分别展示，并标明路径和来源。

### 更新

- 仅更新本应用安装、来源和副本身份均可核实的独立技能；由用户手动触发。
- GitHub 分支来源跟随原分支的新提交；标签来源保持安装时的固定版本，不自动切到更新标签或另一个分支。本地来源重新读取原目录内容并刷新安装副本。
- 更新保留已有启停选择；没有新内容时如实提示，不声称取得了任意上游最新版。
- 对照上次完成安装或更新时的内容基准，发现本地修改就停止并说明原因。首版不合并、不强制覆盖；启停配置变化不算技能内容修改。
- 来源无法访问、目录不再是有效技能或预检查失败时，保留原副本。具体文件保存与恢复机制由实现验证，不宣称文件、来源记录与 Codex 配置之间存在跨文件事务。

### 卸载

- 仅卸载本应用持有且身份可核实的安装副本；确认后把整份副本移入废纸篓，保留 GitHub／本地原始来源。
- 本地修改随副本一并保留在废纸篓中。清空废纸篓前可由用户找回；首版不增加应用内恢复或清空废纸篓功能。
- 不删除共享来源、外部链接目标、插件内容或其他工具的记录。不把内容哈希匹配当作唯一身份凭据，也不按技能名称删除路径。
- 文件操作结果、来源记录处理、Codex 启停配置与原生清单重读分别核对；不能把副本移走后的后续失败报告成“什么都没发生”。

## 实现前能力

- Codex 页面已有「插件市场」与「Hooks」页签。
- 插件详情仅展示技能声明的名称清单，不构成独立技能清单，没有单项技能维护能力。
- 现有 Codex 管理解析一份 Codex home，使用当前用户范围；插件生命周期与独立技能生命周期须分别设计。

## 页面与操作流程

- Codex → Skills 提供搜索、来源与启停筛选；列表区分技能来源、维护资格及原生启用状态，避免把只读或来源不明显示为禁用。
- 详情展示可读的名称、说明、来源、路径及 `SKILL.md`；本应用安装项补充已记录来源和版本。文件缺失或读取失败明确提示，不执行技能内容。
- 所有维护采用单项确认，展示目标及影响；插件技能提供前往所属插件的入口。
- 首次进入、手动刷新及操作后重读；插件／市场维护影响技能清单时使旧结果失效，后续进入时核对。
- 执行前重新检查目标、副本身份、来源及操作资格；发现变化时要求重新读取，不能继续使用过期选择操作另一个对象。
- 操作完成与清单重读分别反馈。重读失败时保留已完成操作的事实并标明清单过期，不能据此重复安装、更新或卸载。

## 验收标准

以下行为已用于实现与验收；已执行检查及真实环境未覆盖项见 [VERIFICATION.md](VERIFICATION.md)。

1. 兼容 CLI 能读取原生技能清单；CLI 缺失、不兼容、错误与空清单有不同反馈，不把其他目录里的项目技能带入当前用户管理。
2. 原有普通目录、共享目录和外部链接技能可查看及修改 Codex 启停，但不能更新或卸载；插件、内置和非用户来源只读。后端也执行这些边界。
3. 原生插件技能即使标为 user scope 也不会成为可维护独立技能；在已验证原生行为下，禁用插件后其技能消失，页面明确范围并保留插件详情入口。
4. GitHub 与本地来源均能安装单个有效技能到当前 Codex home，留下正确的副本和来源记录，新装启用；原始来源保持不变。
5. 安装目录冲突时不改动已有内容；同名不同路径分别展示和定位，不按名称合并或写错对象。
6. 分支更新取得该分支的新内容，标签安装保留固定版本，本地更新读取原目录；更新前后的启停选择一致。
7. 手工修改安装副本后更新被阻止，内容完整保留；来源失败不破坏原副本，启停变化本身不误报为内容修改。
8. 卸载只把选中的应用安装副本移入废纸篓，包括其中的本地修改；原始来源、其他技能及其他工具的文件不受该操作修改。
9. 外部替换目标目录、改成符号链接、篡改维护目标或过期选择时，文件操作被拒绝；配置写入保留无关配置，不以原生返回路径自动授予文件维护资格。
10. 搜索、筛选、只读详情、单项确认与三种刷新时机可用；只读或失败项的原因清晰，保存成功与现有会话加载不混为一谈。
11. 安装／更新／卸载后的重读失败如实保留实际执行结果；文件、记录、配置不一致时说明已完成与未完成步骤，不伪报完整成功。

验证应包含前后端针对性测试及现有回归检查、隔离临时环境中的真实 CLI 核查，以及 Skills 页面的实际交互检查。网络或真实来源未覆盖的部分、所测 CLI 版本和原生桌面端未覆盖的部分须在验证记录中明确。
