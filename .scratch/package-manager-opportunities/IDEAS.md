# Package Manager Control Center：产品创意

## 工作假设

- **产品：** macOS 优先的本机开发环境观察与维护工具。
- **目标用户：** 使用多个包管理器、本地项目、VS Code 和编程代理工具的个人开发者。
- **暂定目标：** 减少用户判断哪些本机开发数据需要关注、以及某项维护操作是否合适时所花的时间与精力。
- **背景：** 产品强调先观察、明确操作范围、限制维护能力，并分别报告执行结果与后续读取结果。以上目标与用户细分是根据仓库内容推断的，尚未得到用户确认。

## 分视角创意

### 产品经理

1. **跨领域维护历史：** 将维护记录从管理器缓存清理和 npm／pnpm 包卸载扩展到项目清理、VS Code 工作区存储移除和会话记录操作，同时保留各领域独立的执行结果与核对信息。
2. **关注事项队列：** 把管理器、项目扫描和编辑器存储中的待关注观察集中到一个排序列表，并展示每项所依据的证据与范围。
3. **目录占用总览：** 比较各领域占用最大的已观察目录，并可跳转到相应详情页；明确区分目录占用与可回收空间。
4. **观察覆盖度总览：** 展示哪些管理器和本机数据来源已有近期观察、哪些已停用或未扫描，以及扫描后能补充哪些信息。
5. **可携带的环境报告：** 导出可保护隐私的本机清单，包含已观察工具、版本、路径、扫描覆盖度和诊断信息，供个人留存或支持排查使用。

### 产品设计师

1. **说明操作资格：** 为不可用或跳过的操作说明具体原因，并关联当前证据，例如不支持该清理方式、测量不完整、目标身份已变化或编辑器仍在运行。
2. **目录详情追溯：** 用户可从高占用目录查看其所属对象、测量完整度、相关候选和允许的后续操作，同时避免暗示目录占用都能被回收。
3. **观察时间标记：** 在摘要和操作附近展示观察时间、观察来源与完整度，让用户了解决策依赖的是新近还是不完整的信息。
4. **按范围审阅选择：** 用户可在管理器、扫描根目录或数据来源范围内审阅条目；确认与结果界面始终清楚展示范围和条目数。
5. **操作回执：** 以易读顺序呈现已确认的目标、执行结果和后续观察，并明确区分读取失败与执行失败。

### 软件工程师

1. **观察来源关联：** 将环境诊断中的命令候选关联到可能对应的管理器观察来源和包路径，帮助解释命令重复或存在多个安装位置的情况。
2. **跨领域快照对比：** 比较项目派生数据候选、VS Code 工作区存储记录和管理器观察随时间的变化，同时保留观察来源身份及读取不完整的说明。
3. **扫描根目录记录：** 为保存的扫描根目录预设关联扫描时间、深度、发现的项目和候选数量变化，方便检查扫描覆盖范围及变化。
4. **能力兼容性视图：** 汇总本机检测到的 CLI 能力，以及这些能力支持哪些清单读取或维护操作；标明版本未经验证的情况。
5. **测量可信度详情：** 说明目录测量为何完整、部分完成或仅为下限，并展示 hardlink 共享如何导致目录占用与实际可回收空间不同。

## 优先级前五

以下评级是相对于当前产品和暂定目标的判断：高、中、低。可行性表示交付一个可验证的首版有多容易，因此“高”代表更容易验证与实现。

### 1. 跨领域维护历史

**已立项：** [PRD](./cross-domain-maintenance-history/PRD.md)

记录产品现有各领域的维护操作，展示冻结的操作目标、执行结果，以及任何后续读取或扫描，并将这些事实分别呈现。

**入选原因：** 这扩展了产品已有的信任基础：管理器清理和包卸载已有维护记录。用户可以回看操作经过，而不会把之后的扫描误认为操作成功的证据。仓库中的项目清理、VS Code 工作区存储移除和会话记录操作已有各自结果模型，因此可以共用历史入口，同时保留每个领域的规则。

**工作量：** 中。多个领域需要持久化记录，并谨慎处理部分完成或结果未确认的情况。

**方向契合度／影响／可行性／差异化：** 高／高／中／高。

**待验证假设：** 用户会回看历史来确认发生过什么；为这些操作持久化记录比仅展示当前操作结果更有价值；用户能找到并理解这些记录，且不需要因此引入统一的删除策略。

### 2. 观察覆盖度与新近度总览

集中展示各管理器和本机扫描来源的启用、停用、未扫描、过期和不完整状态，并提供刷新或调整相应范围的入口。

**入选原因：** 产品已有许多数据来源，总览也展示了一部分扫描状态。随着观察范围扩大，统一视图可以减少用户把“尚未观察”误认为“没有安装内容”的可能，也能在做决定前发现遗漏的范围。

**工作量：** 小到中。大部分数据已经存在，但新近度的定义必须适配各来源不同的读取与扫描周期。

**方向契合度／影响／可行性／差异化：** 高／中／高／中。

**待验证假设：** 用户不确定哪些数据来源已经观察过；统一视图比现有分散状态更容易采取下一步行动；可以定义有用的新近度阈值，同时不暗示较早的观察必然有误。

### 3. 观察来源关联

将环境诊断中的命令候选关联到可能对应的管理器观察来源和包路径，并明确展示无法匹配或存在歧义的情况。

**已立项：** [命令位置关联 PRD](./command-location-association/PRD.md)（功能名采用“命令位置关联”，保留本创意名作为背景。）

**入选原因：** 环境诊断和管理器快照提供了互补视角。将两者关联起来，能帮助用户解释版本重复和 PATH 冲突；这是跨工具排查本机开发环境时常见的困难。

**工作量：** 中到大。关联命令、安装位置和观察来源需要稳定的身份规则，并且必须保留不确定性。

**方向契合度／影响／可行性／差异化：** 高／高／中／高。

**待验证假设：** 用户遇到命令版本不匹配的频率足以支撑此功能；现有路径和管理器元数据能提供有用匹配而不制造确定性假象；关联后的说明比当前分开的视图更易理解。

### 4. 扫描根目录审阅记录

为每个已保存的扫描根目录预设显示最近扫描时间、深度、发现的项目数量，以及与之前扫描相比的候选变化。

**入选原因：** 项目派生数据扫描已经支持保存扫描根目录和深度，但预设目前主要用于重复使用扫描范围。增加少量历史信息，可以帮助用户确认扫描是否覆盖了预期位置，以及自上次审阅后发生了什么变化。

**工作量：** 中。需要持久化项目扫描观察，并在根目录或扫描深度变化时明确处理可比性。

**方向契合度／影响／可行性／差异化：** 高／中／中／中。

**待验证假设：** 用户会足够频繁地重复扫描，从而受益于每个扫描根目录的历史；只有根目录和深度兼容时，候选变化才有意义；保存这些历史的隐私影响与磁盘成本可以接受。

### 5. 说明操作资格

**已立项：** [操作资格说明 PRD](./operation-eligibility/PRD.md)

为禁用、不可用或被跳过的操作说明具体原因，并指出需要哪些证据变化，操作才可能继续。

**入选原因：** 产品有意根据 CLI 支持情况、进程状态、目标身份和观察完整度限制操作。解释这些限制可以减少困惑，同时强化现有安全边界。

**工作量：** 小到中。许多页面已有领域专属状态和错误详情；主要工作是统一呈现方式，并找出缺少原因说明的状态。

**方向契合度／影响／可行性／差异化：** 高／中／高／中。

**待验证假设：** 用户目前会把禁用控件或跳过的条目误解为故障；简短且可采取行动的解释已经足够；不同领域可以复用这种呈现方式，同时不抹平其重要差异。

## 建议的首个实验

使用管理器、项目扫描和 VS Code 页面中的合成状态，制作“观察覆盖度与新近度总览”的原型。请几位使用多个包管理器的开发者指出哪些数据尚未观察，再观察他们会选择刷新、调整范围还是暂时不处理。衡量他们识别状态的准确度和做出下一步决定所需时间；原型不执行任何维护操作。
