# 操作资格说明

Status: in-progress

## 目标与范围

当产品已提供的写操作因当前操作级前置条件或操作目标暂时不能执行时，在相关位置说明有证据支持的阻止原因和可采取的下一步。批量操作在执行时复核资格后跳过目标的，按目标说明原因。用户应能区分操作暂时受阻与产品没有提供该能力。

覆盖当前所有写操作，包括管理器维护、项目清理、VS Code 工作区存储移除、会话记录操作、代理扩展设置与维护。没有合格目标时说明已知原因；尚未选择目标属于选择状态。表单输入校验和已开始执行后的失败分别由表单与执行结果说明。

## 已确认决策

用户于 2026-10-23 通过 `grilling` 访谈确认：

- 操作资格是已提供操作在当前操作级前置条件、操作目标和现有证据下是否可以执行；它不等于能力是否存在，也不包括表单输入有效性。
- 各领域使用一致的原因说明结构，但保留各自的资格规则、原因和恢复边界。
- 在受阻位置直接显示阻止原因；条件明确时同时显示相关证据及恢复条件或下一步，不确定时只陈述已知原因。
- 原因必须可见并可由辅助技术读取，不能只放在 `title` 悬浮提示中。
- 执行时继续核验资格；核验后跳过的目标须逐目标说明原因。确认前说明不取代执行时检查。
- 同时涵盖操作级前置条件和目标级条件。没有合格目标时说明当前原因；尚未选择目标仅属于选择状态。
- 暂时受阻的操作仍在相关位置可发现，并显示受阻原因。产品没有该能力时不显示虚假的禁用操作。
- 仅用户确认上述设计原则，不代表已授权本轮无限扩展代码范围；实现按领域分批，先修复审计发现的资格原因缺失，其他缺口继续留在审计清单。
- 多个已知阻止条件均可说明，只呈现有证据支持的原因。
- 恢复建议复用应用已有的刷新、设置和导航入口，不增加自动修复或新操作流程。
- 已尝试操作的失败仍属于执行结果，不归入资格说明。

## 审计与实现重点

审计发现 VS Code 与多数 Claude/Codex 扩展操作已展示具体原因；主要缺口是原因只出现在悬浮提示、被压缩成泛化标签，或未在没有合格目标时呈现。首轮实现重点：

- 项目清理：禁用选择控件名称说明资格原因；阻止原因与重新扫描等下一步直接可见。
- Codex 技能：呈现已有的具体 `toggleBlocked` 原因，不压缩成“只读”。
- Codex／Claude 会话记录：禁用选择控件说明“使用中”；按年龄移除在零条符合条件时说明门槛及已知排除原因。
- 管理器清理与 npm／pnpm 全局包卸载：维护工作流拒绝请求时显示具体操作级阻止原因。
- 暂时受阻但产品已提供的管理器清理入口保持可发现并就地说明原因；没有清理方案的管理器仍不显示清理入口。

其他写操作保留已有的领域专属原因与执行时复核，不将资格策略合并成通用维护规则。

## 首批实现（2026-10-23）

- 项目清理在受阻候选旁显示身份、测量或清理工具原因，并关联禁用的选择控件；筛选结果没有合格项时给出摘要。
- Codex 技能显示具体的启停限制原因。
- Codex／Claude 会话把“使用中”原因关联到禁用的选择控件；年龄移除说明当前符合门槛数量及已知排除原因。
- OpenCode 年龄删除显示 7／30 天资格数量；没有合格目标时说明近期或运行中会话及父会话的保留规则。
- 管理器维护拒绝请求时反馈原因；已有清理方案在扫描、管理器缺失或 Homebrew 预演未就绪时仍可发现，并说明阻止条件。
- 验证：`pnpm test`（59 个文件、443 项）与 `pnpm build` 通过；Impeccable `detect` 扫描本次修改的 UI 文件未发现问题。

其余写操作按已确认的分批范围保留在后续审计中；本次实现没有改变领域资格规则或执行复核。

## 验收标准

- 对已确认的受阻状态，相关控件附近有直接可读的原因；辅助技术能从控件名称或描述读取原因。
- 有合格目标时操作可用；无合格目标时显示当前没有合格目标及已知资格条件。
- 暂时受阻但能力已提供的操作仍可发现；能力不存在时不显示虚假的禁用操作。
- 所有操作继续在真实执行点复核各自领域的资格；跳过原因与执行失败保持各自语义。
- 文案不把目录占用说成可回收空间，也不把 OpenCode 永久删除说成可恢复移除。

## 明确不做

- 不改变资格规则、执行时机、恢复方式或维护能力。
- 不为表单输入错误或已开始执行后的失败增加资格提示。
- 不新增自动修复、跨领域资格引擎或统一删除策略。
- 不把没有清理方案、只读来源或产品未实现的能力呈现为被禁用操作。
