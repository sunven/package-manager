# 按市场管理已安装 Codex 插件

Status: done

## 已确认的方向（grill-with-docs，2026-10-15）

- 插件属于插件市场，身份由所属市场与插件名称共同确定；以所属市场组织插件管理。
- 市场下只展示该市场已安装的插件，保留现有查看详情、单项启用与禁用能力。
- 本次不新增未安装插件目录浏览，以及独立的插件安装、更新或卸载操作。
- Codex 入口保留「插件市场／Hooks」两个页签，取消独立「已安装插件」页签，并将市场源管理并入「插件市场」。
- 「插件市场」先展示市场列表；展开市场行后，在原页展示该市场的已安装插件及其详情与单项启停操作。
- 已安装项无法匹配市场清单时，仍按插件记录的原市场名分组，标注「未出现在市场清单中」；保留符合现有资格的插件启停，不提供该分组的市场源维护操作。

术语以 [CONTEXT.md](../../CONTEXT.md) 为准。Q2–Q4 及整体方案均已确认；用户授权实现后已完成，结果见 [验收记录](VERIFICATION.md)。

## 沿用的既有边界

- 当前 Codex home、官方已安装清单、用户默认启用设置、单项确认及保存前复核，沿用[插件管理 PRD](../codex-plugin-management/PRD.md)与 [ADR-0011](../../docs/adr/0011-codex-plugins-use-cli-inventory-and-user-config.md)。按市场展示不改变插件身份或维护资格。
- 市场添加、逐个 Git 刷新与移除沿用[市场管理 PRD](../codex-marketplace-management/PRD.md)。移除市场源时，应用不追加插件卸载、插件设置清理或原始来源删除；市场刷新可能同步已配置插件，继续遵循 [ADR-0012](../../docs/adr/0012-marketplace-refresh-follows-codex-sync-semantics.md)。
- 市场清单与已安装插件清单各自具有读取结果与维护资格。没有已安装插件的市场仍属于市场清单；市场只读不自动禁止所属插件的启停。
- 沿用首次进入、手动及操作后读取，区分维护结果与后续重读结果；插件与市场变更后继续使相关清单及 Hooks 失效。

## 已核实的展示约束

- 改动前导航为侧栏「Codex」中的「已安装插件／市场源／Hooks」三个页签；市场行只能展开来源目录详情，没有对应插件列表。
- 插件记录提供所属市场名称，市场清单独立读取。源码允许已安装项找不到匹配的市场清单项；重组时需要为这些项保留展示位置。
- 既有移除市场实验只明确记录插件缓存与启用配置保留，并未证明移除后官方已安装清单必然仍返回原插件，不能把缓存当作已安装清单。

## 页面与操作流程

1. 进入侧栏「Codex」时，默认显示「插件市场」；同级保留「Hooks」。沿用当前页面的视觉样式、列表展开方式、详情字段和确认框，不增加独立插件总览。
2. 首次进入统一页面时，读取同一 Codex home 的市场清单与已安装插件清单。展示实际 home、用户默认设置范围和项目覆盖提示；两份清单各自呈现读取进度与错误。
3. 市场列表保留名称、来源类型、来源地址或路径、市场维护操作及受限原因；没有已安装插件的市场也显示。展开市场行后展示其已安装插件，并保留市场目录详情；插件为空时显示「该市场暂无已安装插件」。
4. 插件列表保留名称、版本、用户默认启用设置、身份及来源详情。使用插件记录的所属市场名称关联市场；同名异市场的插件保持独立身份，操作仍使用完整插件身份。
5. 市场清单成功读取后，无法匹配的已安装项在正常市场列表之后按原市场名分组，显示「未出现在市场清单中」。这类分组只表达插件的来源归属，不冒充已登记市场，不提供该分组的市场源维护操作。其插件的启停资格仍单独判断。
6. 市场清单读取失败时明确显示失败。若已安装清单读取成功，仍按其记录的市场名展示插件，并说明市场信息未能核实；不能将读取失败解释为市场不存在。插件清单读取失败时仍可展示市场及其独立可用的维护操作，插件区域显示读取失败，不显示为零插件。保留旧数据时明确标记过期，不拿旧关联代替执行前复核。
7. 单个插件启停沿用确认、保存前复核和保存后的重读；不因市场只读或清单关联失败而额外禁用原本符合维护资格的插件。命令执行与重读结果分别反馈。
8. 市场添加、逐个 Git 刷新与移除继续在统一页面操作。市场维护命令执行后重读市场与插件清单，并更新分组；失败或部分完成也保留既有的清单失效规则。移除后是否仍显示某个插件，以官方已安装清单为准，不依据缓存或配置推断。
9. 手动「重新读取」读取本机两份清单；「刷新市场」仍是指定 Git 市场的官方同步，两者继续区分。保留已有维护中的操作互斥与重读规则，不新增自动刷新。
10. Hooks 页保留现有管理能力；原「查看已安装插件」入口改为通往「插件市场」并调整文案。插件启停或市场维护后，继续使 Hooks 清单失效并在显示时重读。

## 验收场景

| 场景 | 预期行为 |
| --- | --- |
| 首次进入 Codex | 默认显示「插件市场」，同级仅另有「Hooks」，不再出现独立「已安装插件」页签 |
| 展开含已安装插件的市场 | 原页显示对应插件、详情与原有单项启停能力，不需要切换页签 |
| 市场没有已安装插件 | 市场仍可见，展开后显示已安装插件为空；不展示未安装目录或安装按钮 |
| 不同市场有同名插件 | 分别展示在各自市场下，确认与写入使用完整插件身份 |
| 已安装项无法匹配成功读取的市场清单 | 按原市场名显示分组与明确标注，不漏掉插件，不提供该分组的市场源维护操作 |
| 市场清单读取失败、插件清单成功 | 报告市场读取失败，按插件记录的市场名保留插件及其独立可用的操作，不宣称市场不存在 |
| 插件清单读取失败、市场清单成功 | 市场仍可展示与独立维护，插件区域说明读取失败，不误报为空 |
| 两份清单都成功且为空 | 显示空状态和原有添加市场入口 |
| 市场只读，其插件符合启停资格 | 显示市场只读原因，仍允许按原流程单项启停插件 |
| 插件设置未知、配置异常、目标外部变更或用户取消 | 完整保留既有启停行为和拒绝写入边界，不因页面重组放宽 |
| 市场添加、刷新或移除完成 | 重读两份清单并重新分组，继续区分命令结果和读取结果；不追加插件卸载 |
| 重读失败且保留旧数据 | 旧数据明确标记过期，不被当作当前成功读取结果；保存前仍需重新核实 |
| Hooks 中进入插件管理 | 跳到「插件市场」，入口文案与目标一致 |
| 插件或市场维护后查看 Hooks | 按既有失效规则读取最新清单 |
| 键盘操作或窄窗口 | 市场展开、插件详情和确认框保持可操作；沿用既有焦点恢复与表格局部滚动行为 |
