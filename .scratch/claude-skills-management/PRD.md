# Claude Code 技能管理

状态：已实现；前后端自动化、隔离真实 CLI／Git 验证通过，界面复核及验证边界见 [VERIFICATION.md](VERIFICATION.md)。

## 目标

在现有 Claude Code 入口增加技能管理，接入现有技能管理体验。首版限定当前用户，沿用当前环境的一份 Claude 配置目录，提供查看、搜索、原生调用设置、安装、更新和卸载。

采用「Claude Code → Skills」页签、只读详情和单项维护流程。首版不增加项目管理、技能创作或内容编辑、旧技能接管、批量维护、后台自动更新、强制覆盖或永久删除；入口与这些范围约束已在 Q13 一并确认。

## 已确认的清单与维护边界

Q5–Q8 已确认：

- 统一展示用户范围内可读取的技能定义，包括独立技能、用户已安装插件中的技能、旧版命令、禁用项及可识别的同步技能。标明来源与状态，不将其称为当前会话已加载或可调用的清单。
- 本应用只更新、卸载自己新建且身份可核实的独立技能安装副本。已有普通目录、共享目录和符号链接不接管；已有独立技能可以查看并调整适用的原生调用设置，插件及同步技能只读、交原来源维护。
- Claude 技能调用设置采用原生 `skillOverrides` 的 `on`、`name-only`、`user-invocable-only`、`off`，另提供移除用户覆盖。写入用户设置、按名称生效，可能影响其他项目中的同名技能，也可被项目或更高优先级设置覆盖。
- 正常展示不承诺绕过技能作者的调用限制、权限或组织策略；调用设置不等于文件副本的独占开关或当前会话状态。插件技能随所属插件管理。
- 安装来源支持 GitHub 仓库与本地技能目录。独立技能生命周期由本应用维护安装副本和来源记录，不冒充 Claude 原生安装命令。

领域术语见 [CONTEXT.md](../../CONTEXT.md)，上述取舍记录于 [ADR-0020](../../docs/adr/0020-claude-skills-use-definition-inventory-and-native-name-overrides.md)。下文安装、更新、卸载及兼容性规则由 Q9–Q12 确认，具体验收场景已随完整方案通过 Q13 确认。

## 清单、身份与操作资格

用户定义来自当前 Claude 配置目录的 `skills` 与兼容的 `commands`；插件定义来自归属可核实的用户已安装插件，包括禁用插件。可识别的同步技能只读呈现。项目、组织托管与内置技能不扩展到本轮用户管理范围；不扫描其他项目，也不因为 `.agents/skills` 存在文件就将其视为 Claude 技能来源。经 Claude 用户技能目录中的链接暴露的定义可以读取，但链接不授予内容维护资格。

| 对象 | 查看定义 | Claude 技能调用设置 | 更新／卸载 |
| --- | --- | --- | --- |
| 本应用新建且身份可核实的独立安装副本 | 支持 | 支持已验证的名称设置 | 支持 |
| 已有独立技能，包括普通目录、共享与链接来源 | 支持 | 支持已验证的名称设置 | 不接管 |
| 兼容旧版命令 | 支持 | 仅在原生命令名映射可核实时支持 | 不接管 |
| 用户已安装插件中的技能 | 支持，包含禁用插件 | 返回所属插件管理 | 返回所属插件管理 |
| 可识别的同步技能 | 支持 | 交原来源维护 | 交原来源维护 |
| 来源、名称或文件身份无法核实的条目 | 展示可读内容及问题 | 不提供 | 不提供 |

定义来源、用户调用设置和安装副本身份分别呈现。同名定义按来源与路径区分，不能按名称合并文件或选择删除目标；安装记录与第三方锁文件也不能替代文件身份检查。插件归属、同步来源等限制优先于「位于用户 skills 目录」这一位置事实；含插件身份的目录不能伪装成可维护独立技能。

清单是定义观察，不模拟当前会话的完整名称解析或调用优先级。读取失败、部分来源无法核实、CLI 不兼容和空清单分别表达；插件清单不可用时可继续展示能读到的用户定义，但不能把插件范围报告为已完整读取且为空。

## Claude 技能调用设置

| 用户选择 | 原生值 | 含义 |
| --- | --- | --- |
| 正常展示 | `on` | 向模型提供名称及描述，在用户菜单展示 |
| 仅展示名称 | `name-only` | 向模型仅提供名称，在用户菜单展示 |
| 仅手动调用 | `user-invocable-only` | 不向模型提供该技能，在用户菜单展示 |
| 关闭 | `off` | 从模型与用户菜单隐藏，原生规则拒绝名称调用 |
| 移除用户覆盖 | 删除该名称的用户设置 | 撤销本用户层的选择，不改写技能声明或其他配置层 |

这些是用户层选择，仍受作者声明、权限、项目与更高优先级设置影响。没有用户覆盖时显示「未设置用户覆盖」，不据此宣称当前会话允许调用。`disable-model-invocation` 与 `user-invocable` 是作者声明，不作为本应用启停的替代存储。

修改前展示目标名称、原值、新值及按名称跨项目默认生效的范围；同名或别名存在歧义、无法确定原生命中规则时暂停该操作。只修改用户设置中的目标项，保留其他名称、未知字段与无关配置；源文件发生外部变化时中止旧提交并要求重读。启用选择不会清除已经进入对话的技能内容，也不承诺运行中会话已经采用新设置。

## 安装、更新与卸载

### 安装

- 支持 GitHub 仓库及本地技能目录，单次选择一个独立技能；GitHub 来源可指定技能子目录及分支／标签。
- 复制到当前 Claude 配置目录的 `skills` 子目录，通常为 `~/.claude/skills`。本地导入保留原目录，不创建持续指向来源的链接。
- 保存来源、选定分支或固定版本、技能子目录、安装位置、目录身份及内容基准，供后续维护核实。其他工具的安装记录不授予本应用维护资格。
- 目标目录或当前用户清单中的已知调用名发生冲突时停止，不覆盖、不自动重命名。安装前核实独立技能身份及名称；插件目录、保留名称或无法核实的来源不作为独立技能安装。
- 安装不写入强制 `on`，沿用已有调用设置和技能声明。例如曾关闭 `deploy`，再次安装该名称仍保留原用户选择。
- 确认时展示来源、目标位置与已有调用设置。安装只获取、验证和复制内容，不调用技能或执行其中脚本，不修改原始来源或外部链接目标。

### 更新

- 仅手动更新本应用持有、来源及文件身份均可核实的独立安装副本。
- 分支来源跟随原分支；标签来源固定为安装时选定的版本，不追随移动标签或新标签；本地来源重新读取原目录。
- 保留按名称的用户调用设置。若上游变更调用身份或引入名称冲突，停止更新并说明原因，不自动迁移或重置旧名称的设置；名称及别名判定须经兼容性验证。
- 对照内容基准发现本地修改时停止，不合并、不强制覆盖。调用设置变化不属于技能内容修改。
- 来源失败、内容无效或预检查未通过时保留原副本；没有新内容时如实提示，不声称更新到了任意最新版。

### 卸载

- 仅卸载本应用持有且身份可核实的独立安装副本。确认后将整份副本及其本地修改移入废纸篓，保留 GitHub／本地原始来源。
- 保留按名称的用户调用设置，因为它可能仍作用于其他同名技能；确认界面说明这一点。不清理其他工具的记录、共享内容、链接目标或插件内容。
- 不提供永久删除、清空废纸篓或应用内恢复；清空废纸篓前用户仍可自行找回内容。
- 文件操作、应用来源记录和清单重读分别反馈。不承诺跨文件事务；副本已移动但记录处理或重读失败时，保留实际完成事实，不报告成「未执行」或自动重放卸载。

## 兼容性与操作流程

CLI 缺失或不兼容时，仍展示可读取的定义及原因，暂停写操作。文件存在不证明当前 CLI 支持其语义；未知设置值或无法可靠解释的定义保持只读。

技能能力须单独验证，包括名称／别名匹配、原生四态、作者声明与设置优先级、独立技能校验方式和当前配置目录。当前机器为 2.1.302，已有市场、插件与 Hooks 写入只验证了 2.1.300；新增技能功能不得顺手扩大这些已有写操作的兼容范围。官方文档没有给出完整的最低版本保证，实现须记录实际验证版本和能力，不能仅凭版本号较大开放写入。

已确认的界面流程：

- Claude Code 页新增 Skills 页签，提供搜索、来源与用户调用设置筛选。详情展示名称、说明、来源、路径和只读定义；应用安装项补充来源及版本，插件项提供所属插件入口，同步项解释维护来源。
- 不适用、归属不明、读取失败、未设置用户覆盖与关闭是不同状态，不把只读项目显示成已停用。
- 维护采用单项预览与确认，明确文件目标或设置名称、来源和影响。同一对象维护期间禁止重复提交；执行前重新检查目标、资格、外部修改与当前配置环境。
- 首次进入、手动刷新和操作后重新读取。插件或市场操作影响技能定义时使关联结果失效；后续进入时重新核对。
- 操作结果与刷新结果分别反馈。已完成操作后刷新失败时标明清单过期，不把它当作操作未执行，也不自动重试写入。

## 验收场景

以下是 Q1–Q12 的可验证结果与完整界面方案，已通过 Q13 确认；实现后的测试覆盖及局限见 [VERIFICATION.md](VERIFICATION.md)。

| 场景 | 预期 |
| --- | --- |
| 默认目录及自定义 `CLAUDE_CONFIG_DIR` | 定义、设置、安装副本与操作后刷新使用同一个用户环境，不引入项目管理 |
| 独立技能、旧版命令、禁用插件与同步来源共存 | 按来源呈现可读定义；禁用项不因 SDK 遗漏而消失，不声称已加载 |
| 只有 `.agents/skills` 文件，或 Claude 目录链接到共享目标 | 前者不被自动当成 Claude 来源；后者可读但不取得更新／卸载权限 |
| CLI 缺失、不兼容或插件范围读取失败 | 可读定义仍可见，展示具体限制，暂停写入，不误报完整空清单 |
| 原有技能、插件或同步项位于用户 skills 目录 | 不因位置或第三方记录开放本应用的副本维护 |
| 修改四种原生调用选择、移除用户覆盖 | 只改正确名称的用户项，保留无关设置；明确跨项目默认作用及高层覆盖 |
| 作者声明、项目覆盖、同名／别名歧义、未知值 | 不把用户选择当最终可调用状态；名称无法核实时拒绝写入 |
| GitHub 分支／标签或本地目录安装 | 单项复制到当前用户目录，原来源保留，记录来源与基准，沿用已有调用设置 |
| 目录或已知调用名冲突、插件身份或保留名称 | 安装停止，不覆盖、重命名或把插件作为独立技能接管 |
| 原来源更新、固定标签、无新内容及上游名称变化 | 按已选来源刷新或如实停止／提示，保留调用设置，不自动迁移名称 |
| 本地修改、来源失效、目标被替换为目录外链接 | 停止不符合资格的维护，保留原内容，不操作链接目标 |
| 卸载含本地修改的应用安装副本 | 整份移入废纸篓，来源和按名称设置保留，不修改其他技能或工具记录 |
| 设置文件在预览后被外部修改 | 中止旧提交，保留输入并要求重读，不覆盖外部更改 |
| 插件状态变化或操作后清单刷新失败 | 使相关定义失效，分别显示执行结果与过期清单，不重放写入 |
| 搜索、筛选、详情与单项确认 | 用户能辨认定义来源、维护资格和调用设置，并定位到正确文件或名称 |

实现验证应包含针对性的前后端行为测试、现有回归检查、隔离临时环境中的真实 CLI／配置实验及 Skills 页交互检查。名称匹配等原生事实必须先验证再开放相关写操作；隔离实验不得改用户真实设置或调用技能。已验证版本、未覆盖来源、网络和原生桌面交互局限需在实现后的验证记录中明确。

## 已核实的现有能力

- 当前 Codex 已提供技能查看、搜索、启停、安装、更新和卸载；采用原生发现与启停，本应用只维护自己创建且身份可核实的安装副本。
- 当前 Claude Code 页面提供插件市场与 Hooks；插件详情中的技能声明不构成独立技能管理或会话加载清单。
- 当前 Claude Code 管理限定当前用户，沿用当前 `CLAUDE_CONFIG_DIR`；已有实现的写操作仅向已验证的 CLI 版本开放。这些是现状，不自动决定本功能的范围。
- 现有术语区分独立技能、插件技能与技能安装副本。共享或外部链接技能被某个工具发现，不代表其内容归本应用维护。

现有边界见 [CONTEXT.md](../../CONTEXT.md)、[Codex 技能需求](../codex-skills-management/PRD.md)、[ADR-0019](../../docs/adr/0019-codex-skills-use-native-discovery-and-owned-installations.md) 与 [Claude Code 既有需求](../claude-code-management/PRD.md)。Claude 官方契约与本机版本核查见 [RESEARCH.md](RESEARCH.md)。

关键差异：Claude 的 `skillOverrides` 提供四种原生可见性设置，可用于用户配置，但按技能名称而非安装路径生效，且不适用于插件技能。用户设置可被项目或更高优先级配置覆盖。本轮未发现覆盖停用项的完整原生技能管理清单及通用独立技能生命周期 CLI；SDK 会话清单存在明确遗漏。本机目前为 2.1.302，不等于现有 2.1.300 市场／Hook 写入边界已获得兼容验证。

- 产品目标：Claude Code（Q1 已确认）。
- 核心场景：接入现有技能管理体验（Q2 已确认）。
- 管理作用域：仅当前用户（Q3 已确认）。

- 原生调用设置：四态与移除用户覆盖，接受按名称的用户默认选择及其影响范围（Q7 已确认）。

- 卸载：安装副本移入废纸篓，保留原始来源和按名称的用户调用设置（Q11 已确认）。
- 兼容性：CLI 缺失／不兼容时仍展示可读定义，暂停写操作；技能能力单独验证，不默认放宽市场／Hook 兼容边界（Q12 已确认）。
