# 技能安装副本 module 深化

Status: complete

范围与兼容要求已确认，推荐设计已获确认并完成实现。

## 目标

让 Skill Installation Copy module 集中拥有安装记录与目录观察、文件维护资格、来源准备、安装／更新／卸载及失败恢复。Codex 与 Claude 调用方不再协调可写记录、目录移动和临时目录保留规则。

domain 名称沿用 `CONTEXT.md` 的「技能安装副本」。本轮是现有功能的重构，保留 ADR-0019、ADR-0020 中的归属、发现和设置语义。前端工作流属于另一个候选，不在本轮范围内。

## 已确认的决定

2026-10-17，用户两次回复「按推荐」：

- Q1：采用完整文件维护流程的共享范围，从文件资格与来源副本准备开始，覆盖记录、提交与恢复。
- Q2：允许多个错误同时存在时调整报告优先级；成功、冲突、失败、部分完成等结果、拒绝条件与设置行为保持一致。

## 推荐的 interface 与 seam

建立中性的 Rust module `skill_installation_copy`，供两个代理 module 使用。现有通用文件 implementation 收入其内部；不再通过 `codex_skills::files` 提供共享能力。

主要 lifecycle interface 为观察、准备、提交，辅以只读视图。下列名称表达职责，具体 Rust 命名可按现有风格调整：

```text
observe(home, record_path) → FileObservation
FileObservation.inspect(skill_path) → 只读的安装记录及文件维护资格
FileObservation.prepare(Install | Update | Uninstall) → PreparedCopyChange
PreparedCopyChange.view() → 预览事实与只读的 staged 副本位置
PreparedCopyChange.commit(original_config_observation, trash_adapter)
    → 结构化文件操作结果
```

- `FileObservation` 私有持有安装记录及安装根目录的原始观察。读取失败或文件维护被阻止时，仍支持调用方呈现可读取的记录事实；不能由此阻断原本独立可用的代理清单或设置能力。
- `PreparedCopyChange` 持有来源、版本、确认时的目录身份与内容基准、原始文件观察及临时副本。它不可复制，提交消耗该对象；取消、重扫或替换计划时释放未提交的 staging。
- 只读视图提供 Codex 原生解析所需的临时 home，以及 Claude 定义校验所需的目录与名称。调用方不获得 `TempDir` 所有权、`keep()`、可写 `Ledger` 或目录发布能力。
- 两个代理仍各自管理确认 ID、原生快照、home 解析及现有操作锁。共享 module 不增设 token 注册表、全局工作流或跨代理锁。

## 调用顺序与代理职责

1. 扫描：代理读取其原生清单或定义，结合共享 module 返回的记录与文件资格。记录存在、原生发现和可维护资格继续是不同事实；保留两边既有的展示判定。
2. 准备：代理先检查当前观察与原生资格；共享 module 核实文件观察、取得并冻结来源副本。代理读取 staged 视图完成原生／名称校验，再形成供用户确认的计划。校验失败时释放准备对象。
3. 确认后：代理消耗原有确认计划并复核当前 home、原生清单、兼容性及配置。Claude 继续复核 staged 定义与名称冲突。
4. 提交：共享 module 再核实记录、根目录、安装对象身份、确认内容及 staged 内容。随后检查代理传入的原始 `ObservedFile` 配置观察是否仍未变化，最后执行文件变更与记录保存。
5. 文件结果返回后：Codex 仅在新安装的文件和记录均成功时启用技能；启用失败仍保留已安装事实并报告部分完成。Claude 文件维护保持按名称的调用设置。

最终配置检查使用确认所依据的原始观察，不能重新读取配置并将其当作新的比较基准。共享 module 只检查配置文件是否变化，不解析或写入代理设置。staged 内容复核将代理校验绑定到准备时冻结的副本，不承诺文件、安装记录和配置之间的跨文件事务。

代理保留的差异包括：Codex 原生发现及按路径启停；Claude 定义、名称、别名冲突和更新时名称不变的规则；各自的安装记录文件名、版本兼容要求及用户提示中的设置后果。

## 文件操作与恢复语义

- 安装保持复制来源、拒绝占用的目标、不接管已有普通目录或共享／外部链接的规则。
- 更新遵循记录的来源与版本，遇到本地修改时拒绝；来源内容及版本未变时返回未变化，不改变启停或调用设置。
- 卸载可以包含用户确认过的本地修改，执行前复核确认内容；只将本应用持有的副本移入废纸篓，保留原始来源。
- 卸载先隔离并复核对象，废纸篓操作失败时尝试恢复；恢复无法确认时保留恢复目录并报告部分完成。
- 发布或记录保存失败时，只撤回身份和内容仍与本次发布一致的对象。旧副本无法恢复或当前对象已变化时保留恢复材料，不覆盖后来出现的对象。
- 已移入废纸篓但安装记录保存失败，仍报告部分完成，不把它解释为未执行。
- 共享结果区分已安装、已更新、已卸载、未变化、冲突、失败和部分完成，携带恢复位置等文件事实；代理据此补充设置后果，并保持现有对外结果语义。

## 测试与验收

调用方和测试跨越相同 seam。文件系统使用现有临时目录 fixture；废纸篓保留真实与测试 adapter。必要的故障注入放在私有 I/O seam，避免向外暴露恢复步骤。

共享 module 的测试覆盖：

- 安装、更新、无变化与卸载的文件、来源和记录结果。
- 无维护资格、被替换的根目录／目标、记录冲突、确认后的内容变化和 staged 副本变化。
- 更新拒绝本地修改，卸载保留用户确认的修改内容。
- 取消／替换计划释放 staging，提交对象只能消费一次。
- 最终配置观察变化时拒绝文件变更。
- 发布失败、记录保存失败、废纸篓失败、恢复失败，以及恢复材料实际保留的位置和内容。

代理测试保留：原生拒绝与版本限制、Claude 名称／别名规则、确认重放与重扫失效、配置冲突、Codex 安装后启用及其失败、更新保留设置、Claude 调用设置保留。共用文件故障用例在取得等价结果覆盖后再去重；不为减少数量删除代理差异测试。

完成标准：两个代理调用方不再直接修改安装记录、实施发布／恢复目录移动或决定临时恢复材料的保留；上述行为由共享 implementation 提供，获得两处调用的 leverage 和文件规则的 locality。

## Implementation

2026-10-17，新增 Rust module `src-tauri/src/skill_installation_copy.rs`。`CopyWorkspace` 持有记录和安装根目录观察，提供维护资格检查及 install/update/uninstall 准备；不可复制的 `PreparedCopyChange` 持有 staged 副本和确认时内容基准，消耗式 `commit` 负责最终配置复核、发布／隔离、记录保存、回滚和恢复材料保留。Codex 原生校验与安装后启用、Claude 定义／名称校验与按名称调用设置仍由各自调用方管理。两个调用方及 Claude 定义解析器不再从 Codex module 引用共享文件实现。
