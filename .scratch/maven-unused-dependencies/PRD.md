# Maven 未引用构件清理

Status: done

## 目标与范围

在 Maven 管理器中提供指定项目范围的引用检查与构件版本清理。用户于 2026-11-04 明确选择“扫描指定 Maven 项目，找出扫描范围内未引用的构件”。词汇见 [CONTEXT.md](../../CONTEXT.md)，机制见 [ADR-0036](../../docs/adr/0036-maven-unreferenced-artifacts-use-scoped-trash.md)。

## 行为

- 用户添加最多 20 个项目目录，或选择已有项目清理目录预设；递归发现 POM，排除 `.git`、`target`、`node_modules`、Flutter SDK/生成依赖目录（`.fvm`、`.dart_tool`、`.symlinks`）和代理工具目录（`.agents`、`.claude`、`.codex`、`.grok`、`.opencode`、`.workbuddy`、`.superpowers`），但显式声明的模块仍读取。
- 引用检查不执行构建生命周期，也不下载插件或依赖；只运行 `mvn --version` 以沿用管理器的 settings 仓库来源解析。
- 一轮最多读取 10000 个 POM 模型，并保留 30 秒耗时上限；来源元数据和目录观察不计为模型。超限诊断区分数量与耗时，并显示实际进度和上限。
- 保护所有 profile 声明、传递 POM 引用、父 POM、BOM、插件与扩展。首版按 GA 保护，保留被引用构件的全部版本。
- 本地安装、来源不明、Maven 插件及已知 provider 族保留。默认完整传递引用检查；用户可主动选择“仅检查本地已有 POM”，查看缺失 GA、按有限范围确认清理。缺失模型的传递依赖仍可能使用候选。坐标无法解析、已有构件模型无法读取或扫描不完整时，两种方式都禁用清理。
- 读取父 POM 属性与 CI revision，所有 profile 有限值均保护；按模型容器识别引用，配置同名节点不当作 Maven 声明。支持有界的 JAR 内嵌 POM 读取与执行时内容复核。
- 候选列出坐标、版本、目录占用，支持搜索和逐项勾选；每批最多 200 个版本。
- 确认显示冻结的所选版本和占用，说明指定范围与动态引用限制，以及废纸篓恢复/释放空间的区别。
- 执行前重新计算引用保护；只接受扫描 ID 与候选 ID，不接受前端删除路径。变化、使用中与未知占用跳过；单项失败继续批次。
- 清理移入废纸篓，成功后重新读取 Maven 管理器占用。执行完成或失败后前端要求重新扫描，防止复用旧选择。
- 候选列表支持全选与取消全选；搜索时只操作当前结果，保留隐藏项的选择。批量选择仍受每批 200 个版本上限约束。
- 由 Rust 在执行点写入管理器维护历史，冻结项目范围、仓库与所选构件，逐个记录完成/跳过/失败；历史写入失败不改变清理结果。

## 实际限制

静态 POM 不提供全机或运行时未使用证明；范围外项目和插件动态下载仍可能需要候选。某 GA 任一版本被引用时其他版本也保留。属性继承无法确认、缺 POM、扫描范围内的符号链接、非标准仓库布局、超过扫描预算等情况宁可停止；自动发现排除目录中的链接不阻断扫描。来源记录只证明曾下载，不保证远程副本今天存在。外部构建的并发访问不由本工具完整协调。

## 验证

Rust 验证引用闭包、来源保护、扫描授权、重新分析、路径变化与使用中、所选版本和批次结果；前端验证选目录、搜索后的冻结选择、确认/取消、解析不完整与失败后重扫。实际仓库只读，清理验证使用临时构件与模拟废纸篓。

实现与验证已于 2026-11-04 完成，具体命令、结果和验证边界见 [VERIFICATION.md](./VERIFICATION.md)。
