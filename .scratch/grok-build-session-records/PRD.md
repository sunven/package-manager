# Grok Build 会话记录

Status: ready-for-agent
Implementation: complete

## 目标

在现有「会话记录」页增加 Grok Build 来源，让用户跨项目查找、继续和移除本机会话记录。Q1—Q12 已全部确认，设计访谈完成；本稿包含完整行为、验收场景与实施验证要求。产品代码已实现，验证范围与限制见 [VERIFICATION.md](VERIFICATION.md)。

## 已确认的方向

- 首版提供查看、搜索、年月分组、继续会话，以及单条、明确多选、按 7 或 30 天移除。
- DevScope 只展示足以辨认会话的摘要信息，例如标题、最后活动时间、工作目录；完整对话交给 Grok Build 查看，不增加正文阅读器。
- 复用现有「会话记录」入口，Grok Build 作为独立来源。
- 读取当前解析到的一个 Grok home 下所有工作目录的本机会话记录，包含原工作目录已不存在的记录。遵循 `GROK_HOME`，未设置时使用 `~/.grok`；不提供额外目录选择器，不接入云端。
- 展示每条记录及当前筛选结果的大小，支持按大小排序。统计会话目录内文件，包括附属文件；这些数字不承诺移除后立即释放等量磁盘空间。
- 通过 macOS Terminal，在记录的原工作目录中继续指定 Grok Build 会话。记录或原目录已不存在时提示原因并停止；不自动改目录、创建新会话或创建分支。
- 移除将整条本机会话目录移入废纸篓，保留目录外搜索索引与远端副本，不承诺记录从 Grok 搜索中完全消失；不调用原生永久删除命令。
- Grok Build 退出后才允许移除；检测到仍在运行或无法可靠检查时阻止移除，查看列表仍可用。不把来源级限制误标为每条记录都「使用中」。
- 使用 `last_active_at` 作为最后活动时间；缺失或无效时归入时间未知组，不参与按年龄移除，但仍可明确选择符合其他条件的记录。不用文件修改时间补齐。
- 独立存储的父子／派生记录分别处理，不自动连带移除，也不改写保留记录中的引用。移除父记录时提示关联记录会保留，但指向原记录的引用可能失效。
- 无法确认身份的损坏目录只报告读取异常，不开放移除；能识别的记录仍显示，缺少继续会话所需的信息时仅禁用继续操作，不阻断其他记录。
- 按年龄移除覆盖整个 Grok 来源，勾选只针对当前筛选结果。执行时逐条复核；单条失败继续，发现 Grok 启动或运行状态无法确认时停止剩余操作，分别报告已移入、跳过、失败与未执行。

已确认的移除边界见 [ADR-0030](../../docs/adr/0030-grok-session-removal-preserves-local-recovery-boundary.md)。

## 既有领域约束

- 会话记录属于代理工具拥有的用户数据，不是缓存或项目派生数据。
- 最后活动时间来自记录或相关元数据；缺少时间或工作目录不改变其会话记录身份。
- 不同来源共享确认、执行锁、结果保留和后续读取的生命周期，各自拥有操作资格与执行策略。
- 术语沿用 [CONTEXT.md](../../CONTEXT.md)，操作生命周期沿用 [ADR-0023](../../docs/adr/0023-session-record-operations-share-lifecycle-not-policy.md)。

## 已核实的环境事实

- 本机安装 Grok Build CLI 1.0.70，命令为 `grok`。
- 原生 home 为 `GROK_HOME`，默认 `~/.grok`；记录保存在 `sessions/<encoded-cwd>/<session-id>/`，一条记录是一个目录。
- `summary.json` 提供摘要元数据，`updates.jsonl` 是恢复会话所需的日志。摘要有 `info.id`、`info.cwd`、`created_at`、`updated_at`、`last_active_at`；后两者在本机样本中不总相等。
- `grok sessions list` 仅列当前工作目录的会话；`sessions search` 还使用本地索引与远端结果，不能直接代表跨项目的纯本机清单。
- CLI 支持 `--cwd` 与 `--resume <id>`；省略会话 ID 或整个 resume 参数会产生不同的启动行为，不能用作指定会话继续的回退。
- 官方文档明确 UUID 形状的 resume 参数按 ID 处理，其他值可能按标题匹配。对不能证明会按精确 ID 恢复的自定义标识，不以标题匹配代替指定会话继续。
- CLI 原生 `sessions delete` 是永久删除；目录中存在锁文件不等于会话仍在运行。
- 会话目录外还有 `sessions/session_search.sqlite` 搜索索引，保存会话标识、工作目录、标题与可搜索内容；只移走会话目录不会同时移走这些索引行。
- 父记录的 `subagents/**/meta.json` 可以引用另一条独立存储的子记录；原生删除的级联范围尚未核实。
- 官方文档没有承诺 `sessions delete` 仅作用本机、原子拒绝运行中记录或如何处理索引失败。交互 `/delete` 反而会先停止当前 turn、后台任务及子代理，不能据此推断 CLI 删除会跳过运行中记录。
- `active_sessions.json` 是运行登记线索，但 headless 登记依赖 `GROK_TRACK_HEADLESS`，损坏也可能遗漏；不能单独作为完整的未运行证明。
- 接入前应用有 Codex、Claude Code、OpenCode 三个来源。Codex／Claude 移入废纸篓，OpenCode 通过官方服务永久删除；Grok Build 使用上述已确认的独立移除策略。

本机依据为 Grok Build 1.0.70 随附的 `/Users/sunven/.grok/docs/user-guide/17-sessions.md`：存储结构见第 18、24–42 行，列表范围见第 276 行，登记限制见第 373、400 行，搜索索引见第 426 行；交互删除行为见 `/Users/sunven/.grok/docs/user-guide/04-slash-commands.md` 第 81 行。以上是当前版本的观察，不是对所有版本的兼容性承诺。

## 行为规格

### 读取与展示

- 由后端读取当前 home 的 `sessions/<group>/<session-id>/` 会话目录；只从来源摘要及关系元数据取得展示信息，不读取日志正文来做搜索或补齐缺失字段。文件大小通过文件系统元数据测量。
- 记录身份至少须由预期层级的普通会话目录、可识别的摘要与一致的会话标识确认；不把仅有相似目录名的任意目录当作可移除记录。工作目录、标题或活动时间缺失与身份无法确认分别处理。
- 来源目录内的分组或记录目录为符号链接时，不沿链接发现记录。测量和读取附属数据不跟随链接；整体移除不能作用到链接目标。此约束延续 ADR-0009，并使用 ADR-0030 的目录来源例外。
- 标题使用来源摘要中可识别的原生标题，缺失时显示会话标识；工作目录来自记录元数据，缺失时明确显示未记录。字段映射须以支持格式验证，不用聊天正文生成标题。
- 展示标题、最后活动时间、工作目录、大小及可确认的关联记录信息。关系字段只表达来源中的联系，不将 fork／restore 的来源关系一律解释成子代理关系；缺失关系不靠路径猜测。
- 默认按最后活动时间倒序，按本机日历年月分组并可折叠；时间未知单独成组。可切换按大小排序。搜索标题与工作目录，不查询共享全文索引。
- 大小是目录内常规文件的逻辑长度之和，包含附属文件，不包含外部搜索索引、独立关联记录或链接目标。测量不完整时标明大小未知或部分已知，不把未读部分当作零，也不因此自动判定记录不可移除。
- 延续来源页的进入读取、手动刷新和操作后重读方式，不新增后台轮询。来源不存在显示空；局部异常显示诊断及读取不完整，仍呈现可识别记录；Grok 来源失败不抹掉其他来源。

### 继续指定会话

- 操作前重新确认来源范围、记录身份、原工作目录及 CLI 可用。目录不存在、会话丢失、必要字段缺失或不能保证精确按 ID 继续时，说明具体原因并停止。
- 通过 macOS Terminal 启动原生 CLI，明确指定同一 `GROK_HOME`、记录中的工作目录与会话 ID。经验证的调用形态为 `grok --cwd <cwd> --resume <id>`；环境与参数安全传递，路径或 ID 中的字符不能被解释为额外命令。
- 不省略 ID，不退回最近会话、标题模糊匹配或新会话，不加 fork／restore-code 参数。若某个 ID 格式无法通过原生入口可靠继续，该记录仍可查看，并按独立资格判断能否移除。
- 将启动交互交给 Grok Build；本工具不复制正文，不提供本地阅读器。DevScope 的本机读取边界不代表原生 Grok 继续会话时离线运行。

### 确认与移除资格

- 操作只作用于当前来源。单条确认显示记录标题／标识；多选确认显示已选范围；按年龄确认显示 7／30 天门槛与当时观察到的数量。取消确认不执行移除。
- 确认明确说明整条本机记录移入废纸篓、清空前可恢复、搜索索引与远端副本保留、物理空间不会立即按展示数字释放；存在已知关联时提示独立关联记录不会自动移走且原引用可能失效。
- 全选仅选择当前筛选结果中符合明确选择资格的记录；筛选变化时沿用现有选择清空规则。按年龄操作作用于整个 Grok 来源，不受搜索条件、月份折叠或当前选择限制。
- N 天指 N 个 24 小时；最后活动时间必须严格早于确认门槛才进入按年龄移除。按年龄冻结来源范围、规则与门槛，执行时重新确定候选，沿用 ADR-0007 与 ADR-0027 的语义；确认数量不等于执行总数。
- 单条与明确多选冻结指定记录身份，不因活动时间更新而取消选择；仍须满足身份与运行保护。按年龄记录则在实际移除前重新读取时间，变为近期或未知的记录保留。
- Grok Build 仍在运行或无法可靠判断是否已退出时，来源不能开始移除。运行检测须覆盖支持范围内的交互、headless、agent 与会话宿主；不能仅凭缺少登记、锁文件存在与否或一个进程名称未匹配就判定可操作。
- 保留 ADR-0006 的使用中保护：记录数据仍被其他进程打开时不移除；不能证明这一条件时保留并说明原因。Grok 来源级运行限制与单条「使用中」分别呈现。
- 每条移除前重新确认当前来源、记录身份、目录边界、运行状态及适用的年龄资格。来源范围变化时拒绝旧确认并要求刷新。目录消失、变为链接或身份不再可信时保留／跳过，不扩大操作目标。
- 整条记录移入废纸篓，不修改来源内的共享索引、分组元数据、其他记录、项目目录或 Grok 工作树。独立子／派生记录只有在被明确选中或自身满足年龄规则时才成为目标，不由关系级联授权。

### 执行结果与既有能力接入

- 一次确认按序执行。普通单条移除失败不中断其余记录；检测到 Grok 启动或运行状态未知时，停止后续操作，未动手项报告为未执行。已成功项留在废纸篓，不回滚。
- 分别报告已移入、跳过、失败与未执行；跳过或停止的原因可辨认。失败与未执行不能被归入成功，后续读取失败也不能改写已经确认的执行结果。
- 批量移除沿用共享操作生命周期与每次调用的进度机制，显示执行时确认的候选总数及累计结果；不以前端逐条独立调用替代后端批量资格复核。执行结束忽略迟到的进度消息。
- 完成后重读 Grok 来源。按现有规则保留仍需用户处理的失败与未执行选择，再次操作重新确认。
- 按 ADR-0028 为 Grok 来源注册稳定观察项、来源范围与完整性信息。按 ADR-0027 将真实移除结果与后续读取分别记录到维护历史，不持久化会话正文。不得将会话占用加入可重建缓存或项目清理的可回收空间。

## 验收场景

| 场景 | 预期行为 |
| --- | --- |
| 一个 home 下有多个工作目录的记录 | 全部可识别记录出现在 Grok 来源，其他 home 与远端不参与读取 |
| 原项目目录已被删除 | 记录仍显示；继续操作说明原目录不存在；符合其他资格时仍可移除 |
| GROK_HOME 未设置／指定其他 home | 分别使用默认位置／指定位置，继续与移除使用同一来源 |
| 日志、附属文件和独立子记录同时存在 | 单条大小只计该记录目录内文件，独立子记录另外计量 |
| 记录或分组为链接，或内部链接指向目录外 | 不沿链接发现、读取、测量或移除目标 |
| 摘要损坏或身份不一致 | 报告读取异常，不开放该目录移除；其他记录仍可使用 |
| 标题、工作目录或时间缺失，但身份可确认 | 展示标识与缺失状态；工作目录缺失不能继续，时间缺失不参与按年龄移除 |
| 文件大小测量部分失败 | 展示不完整状态，汇总不把缺失部分伪装为零 |
| updated_at、last_active_at 与文件修改时间不同 | 分组和按年龄资格仅使用有效 last_active_at |
| 活动时间刚好等于 7／30 天门槛 | 不属于严格早于门槛的目标 |
| 搜索只显示部分记录后使用按年龄操作 | 确认清楚指向整个 Grok 来源；全选则只选择当前筛选结果 |
| 继续前会话丢失、CLI 不可用或 ID 无法精确恢复 | 提示具体原因，不转成新会话、最近会话或标题匹配 |
| Grok 正在运行或检测无法完成 | 列表可读，来源禁止移除，不能把全部记录误标为使用中 |
| Grok 已退出但另一个进程打开记录数据 | 对应记录保留；其他资格可核实的记录按规则处理 |
| 确认后 Grok 启动 | 执行时检测到即停止剩余移除，保留未执行项；不承诺最后检查与启动之间原子互斥 |
| 按年龄记录在确认后出现新活动 | 动手前重读时间后跳过；明确选择不只因时间改变被取消 |
| 一条记录移入废纸篓失败 | 记录该项失败并继续其余项；成功项不回滚 |
| 父记录很旧，独立子记录很新 | 按年龄只处理自身符合资格的记录，不因父记录入选而移走子记录，不改写引用 |
| 父与子都被明确选中 | 两个独立目标分别处理，不能把其中一项当成隐含级联成功 |
| 移除完成 | 整条记录目录进入废纸篓，目录外索引与远端副本不变，界面如实说明残留边界 |
| 移除成功但后续列表读取失败 | 成功结果仍保留，同时报告读取失败；维护历史区分两种结果 |
| 批量中停止、零候选或进度迟到 | 不报告虚假的完成数量，不残留上一批进度；零候选不发起无意义确认 |

## 实施验证要求与已知限制

- 当前事实来自 Grok Build 1.0.70；记录身份、摘要字段映射与时间格式要以匿名化结构 fixture 验证，不把该版本观察扩写为所有版本的承诺。不兼容记录按 Q10 降级，不能猜测后继续或移除。
- 需要验证正常退出后可以移除，以及交互、headless、agent、后台宿主存在或检测失败时确实阻止操作；不能用一律禁用移除替代首版已确认的能力。单次进程检查没有与 Grok 启动的原子互斥，不承诺消除全部竞态。
- 非 UUID 自定义 ID 的精确恢复入口与不同宿主的路由行为仍需验证；未通过验证的格式禁用继续，不影响其读取与独立移除资格。
- 独立存储不证明关联记录的所有恢复能力都不依赖原记录。本设计只承诺不连带移除、不改写引用，不承诺移除父记录后保留记录的所有原生操作完全不受影响。
- 验证用临时 home、合成会话目录、模拟进程状态与废纸篓替身，不用真实用户会话做删除实验。覆盖资格重判、年龄边界、链接边界、部分失败、运行状态变化及正确启动参数；前端只验证用户可见流程与既有生命周期接入，不重复内部实现测试。
- 索引维护、远端删除及原生永久删除的内部行为不再是本方案的实施依赖，因为本工具不执行这些操作。

## 不在本次范围

- 对话正文阅读器、正文搜索、改名、分支、改工作目录、代码恢复、应用内会话恢复入口。
- 云端记录、多 home 管理、目录选择器、共享索引清除或修复、Grok 工作树移除。
- Grok 配置、模型、技能、插件或凭据管理；永久删除与彻底抹除。

## 设计树与确认状态

- 能力范围：已确认完整接入。
  - 观察范围：已确认当前 home、跨全部工作目录、仅本机记录。
  - 摘要信息：不展示正文、展示占用与按大小排序已确认；缺失、损坏与不兼容记录按 Q10 处理。
  - 继续会话：已确认通过 Terminal 在原工作目录继续指定记录；目录或记录失效时停止并说明原因。
