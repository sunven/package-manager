# 管理器观察来源

状态：已实现。用户于 2026-10-21 确认方案并要求实现。

所有管理器由扫描 module 交付观察来源，历史 module 只持久保存这些事实。扫描入口直接返回带 `scope_key` 的快照，不再在扫描后补做来源探测。

来源无法核实时保留已读取的内容，但不据此计算历史差异。非 Docker 扫描复用本轮读取的安装路径及解释器；保持已知安装范围的原有编码，拒绝空路径、相对路径、不可核实的解释器及不完整的 uv 来源。Bun 只有在清单头部确认预期全局目录时才沿用安装根目录身份，其他情况保留未知。

Docker 通过原生 CLI 选择有效 context，导出并导入扫描专用临时配置。此流程同样适用于包含 DOCKER_HOST/TLS 设置的 default context，避免自行重写 Docker 的选择规则。全部身份和清单查询共享冻结后的 context；复制 HTTP headers，TLS 材料随 context 保留，临时文件随扫描结束释放。

资源读取前后的 daemon ID 必须非空且一致，才生成 `["docker-observation-source-v2", endpoint, daemonId]`。无法固定连接或核实身份时不生成来源标识，仍返回可读内容和错误原因。历史错误摘要不保留扫描临时路径。

Docker 旧快照保持可查看，不回填新来源标识，不与新标识自动比较；相同新来源且清单完整时正常比较。来源绑定不承诺跨资源查询的同一时刻事务快照。

验证和限制见 [VERIFICATION.md](VERIFICATION.md)。
