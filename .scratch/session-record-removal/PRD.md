# 会话记录移除

术语以 CONTEXT.md 中的「会话记录」「最后活动时间」「工作目录」「使用中」「会话记录移除」为准。取舍见 docs/adr/0005 到 0009。

## Problem Statement

Codex 和 Claude 的对话文件会在本机 home 里越积越大。这些文件是对话内容，删了不能重建，也不是包管理器缓存或项目派生数据。现在要看清它们、腾出原目录，只能到另一个工具里管理，而且那个工具按文件修改时间永久删除，和本工具对「清理」的承诺对不上。

## Solution

本工具增加独立的一页，分别观察 Codex 与 Claude 的会话记录，并可以把选中的记录移入废纸篓。按年龄的批量移除使用会话记录内部的最后活动时间。使用中的记录留在原处。确认只作用于一个来源，动手时再判断一次资格。

## User Stories

1. 作为本机开发环境的使用者，我希望有一页专门看会话记录，以便把它和项目清理、开发体检分开。
2. 作为本机开发环境的使用者，我希望同一页里 Codex 和 Claude 分区显示，以便我知道自己正在看哪一个来源。
3. 作为本机开发环境的使用者，我希望每次进入这一页都重新读取两个来源，以便离开页面期间发生的续写和开关进程能反映出来。
4. 作为本机开发环境的使用者，我希望留在页面上时可以手动刷新，以便不必离开再进来。
5. 作为本机开发环境的使用者，我希望只看到当前环境解析到的那一个 Codex home 和那一个 Claude home，以便不会误动另一个目录。
6. 作为本机开发环境的使用者，我希望 Codex 只列出该 home 下 sessions 里的会话记录，Claude 只列出该 home 下 projects 里的会话记录，以便其他文件不混进来。
7. 作为本机开发环境的使用者，我希望符号链接不出现在列表里，以便移除不会跟着链接去动目标文件。
8. 作为本机开发环境的使用者，我希望每条记录显示标题、最后活动时间、工作目录和大小，以便我认得出将要移走的是哪一段对话。
9. 作为本机开发环境的使用者，我希望没有工作目录的记录仍然列出，并且工作目录那一格为空，以便缺了位置信息也不会把记录藏起来。
10. 作为本机开发环境的使用者，我希望记录按最后活动时间的年、月分组，新的月份在前，以便在几百条记录里找到某一段时期。
11. 作为本机开发环境的使用者，我希望月份可以折叠，组上显示条数和体积，以便不展开也能看出哪个月占空间。
12. 作为本机开发环境的使用者，我希望读不出最后活动时间的记录单独成一组，以便它们不会被算进某个月份。
13. 作为本机开发环境的使用者，我希望使用中的记录留在所属月份里，并标明现在不能移除，以便我知道它还被代理开着。
14. 作为本机开发环境的使用者，我希望一个来源的目录不存在时，这一区显示为空，而不是整页失败，以便另一个来源仍可使用。
15. 作为本机开发环境的使用者，我希望一个来源读取失败时，另一来源的记录仍然显示，以便一次失败不挡住全部。
16. 作为本机开发环境的使用者，我希望看到每个来源的记录数和总占用，以便判断值不值得移除。
17. 作为本机开发环境的使用者，我希望占用表示会话记录离开原目录的体积，并写明物理空间要等废纸篓清空才释放，以便我不会以为磁盘已经腾出来。
18. 作为本机开发环境的使用者，我希望可以单条移除一条会话记录，以便只丢掉我认出来的那一条。
19. 作为本机开发环境的使用者，我希望单条移除前的确认写明这条记录的标题，以便我核对是不是要移走的那一段。
20. 作为本机开发环境的使用者，我希望可以把一个来源里最后活动时间早于 7 个 24 小时的记录批量移入废纸篓，以便清掉一周前结束的对话。
21. 作为本机开发环境的使用者，我希望可以把一个来源里最后活动时间早于 30 个 24 小时的记录批量移入废纸篓，以便清掉一个月前结束的对话。
22. 作为本机开发环境的使用者，我希望批量确认写明来源、天数和将移入废纸篓的条数，以便我知道这次动的是哪一边、动多少。
23. 作为本机开发环境的使用者，我希望批量确认说明使用中的记录和读不出最后活动时间的记录不在这批里，以便我不会以为它们也被移走。
24. 作为本机开发环境的使用者，我希望一次确认只移除一个来源，以便看着 Claude 的数字确认时不会连带移走 Codex。
25. 作为本机开发环境的使用者，我希望读不出最后活动时间的记录只能单条移除，以便年龄未知的对话不会被批量门槛卷走。
26. 作为本机开发环境的使用者，我希望使用中的记录不能单条移除，也不能进入批量，以便进行中的对话不会被移走。
27. 作为本机开发环境的使用者，我希望取消确认时什么都不移走，以便我可以退出。
28. 作为本机开发环境的使用者，我希望当前没有符合年龄条件的记录时，不发起一次空的批量确认，以便不会确认一个零条动作。
29. 作为本机开发环境的使用者，我希望文件真正移入废纸篓时再判断一次资格，以便确认之后被续写或被打开的记录能留下来。
30. 作为本机开发环境的使用者，我希望按年龄移除在动手时发现最后活动时间已不再早于门槛，就留下该记录，以便刚续写的对话不被旧名单移走。
31. 作为本机开发环境的使用者，我希望按年龄移除在动手时发现记录已在使用中，就留下该记录，以便刚被打开的文件不被移走。
32. 作为本机开发环境的使用者，我希望单条移除在动手时发现它已在使用中，或已不再是会话记录，就留下它，以便确认之后的变化仍然有效。
33. 作为本机开发环境的使用者，我希望单条移除不因为最后活动时间更新而取消，以便我明确选中的那一条仍会被移入废纸篓。
34. 作为本机开发环境的使用者，我希望做完后看到实际移入废纸篓的条数和失败的条数，以便确认时的数字和结果不一致时我能看出来。
35. 作为本机开发环境的使用者，我希望一批里某一个文件移入废纸篓失败时，其余符合条件的文件继续移，以便一次权限或名字冲突不留下整批。
36. 作为本机开发环境的使用者，我希望已经移入废纸篓的记录保持在废纸篓里，即便后面有文件失败，以便成功的那部分不倒退。
37. 作为本机开发环境的使用者，我希望移除之后列表变成动手之后的结果，以便已经离开原目录的记录不再出现。
38. 作为本机开发环境的使用者，我希望会话记录的占用不进入开发体检的维护候选空间，以便体检不会把不可重建的对话说成可清理空间。
39. 作为本机开发环境的使用者，我希望年月分组按本机本地日历理解最后活动时间，以便月份和我看到的日期一致。
40. 作为本机开发环境的使用者，我希望批量移除针对整个来源，而不是针对展开的某一个月，以便月份只是查看方式。

## Implementation Decisions

- 新增与项目清理、VS Code 占用并列的一页。页内两个来源分区。导航名称用「会话记录」。开发体检不读取、不汇总会话记录。
- 列表与移除由一个 Rust 模块负责，前端通过按来源区分的命令读取和移除。前端不自行遍历磁盘，也不自行决定某个路径可以移入废纸篓。
- 每个来源只解析一个 home。Codex：有 `CODEX_HOME` 用它，否则用用户主目录下的 `.codex`，记录只来自其中的 `sessions`。Claude：有 `CLAUDE_CONFIG_DIR` 用它，否则用用户主目录下的 `.claude`，记录只来自其中的 `projects`。不提供目录选择器。
- 会话记录是该目录树内的普通 `.jsonl` 文件。目录、其他扩展名和符号链接都不是会话记录。移除时重新确认：路径仍在该来源目录内，仍是普通 `.jsonl` 文件，不是符号链接。不跟随符号链接。
- 一条会话记录对外至少包含：来源、来源目录内的相对身份、标题、最后活动时间或「没有」、工作目录或「没有」、文件大小、是否使用中。标题来自记录内容；内容里没有标题时用文件名。大小是文件的逻辑长度。
- 最后活动时间是记录内容里出现的最晚时刻，不是文件修改时间。两个来源各自解析自己的内容，产出同一组字段。
- 使用中指文件仍被其他进程打开。列表和移除使用同一个判断。
- 「N 天前」指最后活动时间早于当前时刻减去 N 个 24 小时。本页只提供 7 和 30。年月分组把该时刻换成本机本地日历的年和月。
- 移入废纸篓是可替换的动作。移除模块决定哪些路径符合资格，再把这些路径交给该动作。测试用替身记录路径，不调用系统废纸篓。
- 按年龄移除和单条移除都是一次一个来源。按年龄移除的资格在每个文件动手时重判：仍早于门槛、未在使用中、仍是会话记录。单条移除重判：仍是会话记录、未在使用中；最后活动时间变了仍移除。
- 单个文件失败不阻止同一来源里其余仍符合资格的文件。结果包含实际移入的条数和失败的条数。已经交给废纸篓动作的文件保持已移交。
- 来源目录不存在视为该来源没有记录。一个来源的读取错误不抹掉另一个来源已经得到的记录。
- 当前读取里，某来源符合某年龄门槛的条数为零时，不打开该次批量确认。
- 移除成功后重新读取受影响的来源，并用结果里的条数说明实际移入多少、失败多少。

## Testing Decisions

好的测试只断言外面看得到的行为：哪些记录被列出来、哪些路径被交给废纸篓动作、哪些被留下、结果条数是多少。不断言解析过程的内部结构，也不点击真实界面，也不碰使用者本机的 home 和系统废纸篓。

- Rust 模块是最高的接缝，用临时目录。覆盖：只列出普通 `.jsonl`；符号链接、目录和其他文件不出现；最后活动时间、工作目录和大小；使用中的记录被标出且移除时被跳过；7 个和 30 个 24 小时的门槛；动手时最后活动时间已更新或变为使用中则按年龄移除留下它；单条移除在时间更新后仍移交、在变为使用中后留下；一个文件失败时其余继续，结果条数正确；来源目录不存在是空列表。
- 前端策略测试覆盖：按本地日历的年月分组且新的月份在前；读不出最后活动时间的单独成组；一次确认只描述一个来源，并带有天数和符合条件的条数；使用中的记录和读不出最后活动时间的记录不计入批量条数；符合条数为零时不形成批量确认。
- 既有参照是项目清理模块的 Rust 测试、VS Code 占用模块的 Rust 测试，以及项目清理的前端策略测试。

## Out of Scope

- 阅读对话正文、恢复会话、编辑 Codex 或 Claude 的配置。
- 显示消息数、CLI 版本或模型。
- 自选目录、第二个 home、Codex 与 Claude 以外的代理。
- 移除 `.jsonl` 以外的附属文件。
- 按月份批量移除，或自定义天数。
- 永久删除。
- 把会话记录放进项目清理的批次，或放进开发体检的占用与维护候选。
- 以页面点击或真实废纸篓作为本 PRD 的测试。

## Further Notes

- 本机抽样时，体积几乎都在对话文件本身：Codex 的 sessions 约 156MB 的 `.jsonl`；Claude 的 projects 约 466MB 的 `.jsonl`，旁边其他文件约 5MB。因此移除对象就是会话记录这个文件。
- 确认框里的条数是确认当时的观察，可以大于实际移入废纸篓的条数。
