# Claude Code 市场、插件与 Hooks 管理

Status: done

## 已确认的方向（grill-with-docs，2026-10-15）

- 参考当前应用的 Codex 市场、插件与 Hooks 管理，设计 Claude Code 版。
- 第一版只管理当前用户，不纳入项目配置或扫描发现的项目。
- 只管理市场插件，覆盖详情、安装、更新、卸载、启用和禁用；采用 Claude 原生操作，特殊来源不纳入首版。
- Hooks 提供用户定义新增、编辑、删除，以及插件 Hook 只读查看；不提供单项启停，不引入由本工具保存的停用定义。插件 Hook 随插件整体启停。
- 保留市场移除操作，确认前列出连带影响；影响涉及非用户范围或无法确定时阻止。
- CLI 缺失或不兼容时，可展示可读取的用户 Hook 定义和原因，但暂停全部写操作；市场和插件管理要求兼容 CLI。
- Hook 使用结构化表单编辑单条定义，原始配置只读；保留未编辑条目与未知字段。
- command、http、mcp_tool、prompt、agent 五种 Hook 配置类型全部支持，按事件与类型约束校验；不在本工具执行测试。
- Hook 清单展示用户设置中的定义，以及全部用户已安装市场插件声明的 Hook，包括禁用插件；标记来源和插件状态，不将其表述为会话运行清单。技能、子代理等局部 Hook 暂不展开。
- 用户 Hooks 总开关关闭时仍可维护定义，只展示开关状态；保存不自动打开，首版不提供总开关操作。
- 插件维护遵循官方依赖规则：操作前说明可能联动，完成后重读清单；原生拒绝时展示原因，不自行强拆依赖，仍限定用户范围。
- 插件详情仅读取目录信息与已有的本地可访问内容；远程未下载内容可以不完整并明确标记，不为预览主动下载源码。
- 市场添加支持 GitHub/Git、本地目录或 marketplace.json 文件、远程 marketplace.json，以及 Git ref/sparse；claude.ai 托管来源不提供添加入口，现有托管或归属不明来源只读。添加市场可能补装缺失依赖，按原生规则说明并反馈。
- Q1–Q13 已确认，现已完成实现与验证；具体结果及版本边界见 [VERIFICATION.md](VERIFICATION.md)。

## 参考基线与事实

- Codex 当前入口包含「插件市场 / Hooks」两个页签，插件浏览与操作嵌在市场内。
- 对齐参考包含市场添加、查看、同步、移除，插件详情、安装、重新安装、卸载、启停，以及用户 Hook 定义新增、编辑、删除。Claude 使用其原生更新操作，不继承 Codex 的重新安装语义。
- Claude 插件有官方生命周期与启停 CLI；Hook 没有已公开的逐项禁用状态契约。不能只替换 Codex 名称与配置路径。
- 官方来源、版本局限与待核实事实见 [RESEARCH.md](RESEARCH.md)。

## 已确认的完整方案

### 入口、范围与事实来源

- 在当前应用新增独立「Claude Code」入口，沿用 Codex 的「插件市场 / Hooks」两页签结构；插件在市场内浏览与维护，既有会话记录继续保留原入口。
- 解析当前用户的 `CLAUDE_CONFIG_DIR`，未设置时使用默认 Claude 配置位置。读取与执行保持同一个用户环境，CLI 从项目外上下文执行，所有支持 scope 的写操作显式指定 user。
- 安装事实来自官方 CLI，不能从缓存或配置条目推断已安装。维护前复核来源归属、安装作用域与目标身份；托管、归属不明或不受支持的来源只读。
- 可读取非 user 安装记录，用于跨范围影响检查；不因此提供项目管理，也不把项目外 CLI 的 enabled 值当成其他项目的实际状态。
- 定义、安装、启用选择、用户总开关与现有会话加载分别表达。兼容 CLI 缺失时仍可查看可读取的用户 Hook 定义，写操作暂停，清单读取失败不能显示为「没有插件／没有 Hook」。

### 市场与插件

- 市场提供列表、展开浏览、添加、逐个更新市场目录及移除。添加来源遵循官方 CLI，Git ref 编码进来源，sparse 仅用于支持的 Git 来源；不扩展为直接编辑市场源配置或自动订阅市场。
- 插件提供市场内名称／简介搜索、全部／已安装／未安装筛选、详情，以及单项安装、更新、卸载、启用和禁用；同名插件按市场区分，特殊插件来源不加入本轮维护。
- 详情显示目录元数据与可读取的本地组成，缺失、不支持或读取失败分别说明。只读查看不自动安装或下载源码，不据本地文件存在重建安装清单。
- 更新市场目录与更新已安装插件分别呈现。2.1.300 隔离实验中，具名市场 update 不刷新插件安装副本；不沿用 Codex 的「市场同步可能刷新插件」或「重新安装会启用」语义，后续兼容版本须核实各自行为。
- 添加市场、安装与启用可能连带补装或启用依赖，确认时说明原生联动，结束后重读清单。禁用因依赖被拒绝时显示原因，不强拆依赖，不自行建立第二套依赖求解。
- 移除市场前重新读取该市场全作用域安装记录。存在 project/local/其他非 user 安装、归属不明、清单不完整或无法确定影响时拒绝移除；仅用户范围内也须列出受影响插件，并说明官方可能处理相关插件数据。--scope user 不能代替影响检查。
- 插件／市场维护后重新读取关联清单并使 Hook 定义展示失效。成功操作后的重读失败单独报告，不把操作重放；需要认证或交互时交回 Claude 原生流程处理。

### Hook 定义与编辑

- 用户定义来自用户 settings 的 hooks 字段；插件定义只读读取全部用户已安装市场插件的默认文件和 manifest 附加声明，包含禁用插件。插件文件不可读时保留安装事实并显示读取问题，不标记为「无 Hook」。
- 列表和详情明确事件、匹配条件、类型、处理内容、定义来源与插件状态。原始内容只读，技能／子代理局部 Hook 与 mod 函数 Hook 不纳入；不提供逐条启停、Codex 式信任状态或完整运行清单。
- 新增、编辑采用结构化表单，覆盖 command/http/mcp_tool/prompt/agent。公共和高级字段按官方事件、类型与版本条件展示，不把被忽略或从不生效的组合做成有效配置。未知事件／类型只读，agent 类型说明其原生实验性。
- 第一次新增只创建必要的用户 hooks 结构；既有定义原位维护。每次只编辑目标 handler，共享 matcher 改变时拆出目标，保留其他定义、组属性、未知字段与无关设置；不迁移、去重或重建整份配置。
- 保存前展示本次定义变化，删除确认目标定义和来源；删除只移除所选定义，不删除其引用脚本或其他资源。不在本工具执行命令、HTTP 请求、MCP 工具或提示词来测试 Hook。
- 外部修改检测覆盖完整来源文件。源文件变化时保留表单、中止旧提交，重读后重新确认；解析失败或无法可靠保留原内容时只读，不自动覆盖重试。
- 用户 disableAllHooks 关闭 Hooks 时仍可查看及维护定义，只显示用户选择及其作用范围。保存保留总开关，不提供开关操作或逐条信任；不声称项目与托管 Hook 已全部停止。

### 兼容性与结果反馈

- 分别验证清单、市场变更、插件生命周期及 Hook 字段能力。官方 JSON 支持下界和本机 2.1.300 实验均是依据，不将其扩大成未经验证的跨版本保证；不能确认所需能力时只读并显示原因。
- 维护命令使用结构化参数，解析最终 JSON 行并检查退出码；没有机器可读结果时不降级为猜测人类文本，也不把空输出当成功。
- 同一对象维护期间禁止重入；过期清单不可直接提交。失败保留用户输入，部分结果、操作失败和刷新失败分开反馈，不承诺跨文件或 CLI 操作事务，也不自动重试写入。
- 本轮是手动、单项配置维护；不增加批量操作、后台同步、操作历史、运行排障、脚本测试或认证管理。

### 验收场景

| 场景 | 预期 |
| --- | --- |
| 默认路径与自定义 CLAUDE_CONFIG_DIR | 读取、维护及操作后刷新均使用同一个用户环境 |
| 市场声明可见但归属非 user 或不明 | 可以查看，不能从该来源入口维护 |
| 添加 Git、本地或远程 JSON 市场 | 使用相应原生来源；ref/sparse 仅按支持规则提交；提示可能补装依赖 |
| 更新市场中的插件源版本 | 更新市场目录与插件更新分别操作，不将目录版本冒充安装版本 |
| 同市场有项目／local 安装 | 即使传 --scope user 也阻止市场移除 |
| 仅用户安装的市场被移除 | 确认列出连带插件与数据影响，执行后重读；不承诺缓存全部删除或回收量 |
| 插件安装／启用涉及依赖，禁用被依赖阻止 | 采用 CLI 结果，正确展示联动或拒绝，不强拆依赖 |
| 未下载的远程插件查看详情 | 展示可读信息及缺失原因，不自动下载或安装 |
| 插件已禁用或插件文件读取失败 | 禁用插件定义仍可查看；读取失败不误报无定义 |
| 五种 Hook 类型及不支持的事件组合 | 正确表单与校验，未知类型只读，无法生效的组合不能作为有效配置提交 |
| 编辑共享 matcher 组中的一个 handler | 只改目标，其他定义与未知字段保持，必要时拆组 |
| 删除引用外部脚本的 Hook | 只删定义，保留脚本及无关设置 |
| 用户总开关关闭 | 可维护定义，保存不打开开关，不显示为逐项停用状态 |
| 文件被外部修改／格式无法解析 | 中止旧写入、保留输入或只读，不覆盖外部内容 |
| CLI 缺失／不兼容／清单或重读失败 | 可读用户定义仍展示；暂停写入；不把读取失败伪装成空清单或重放已成功操作 |
