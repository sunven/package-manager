# Codex Hook 配置管理

Status: done

## 已确认的方向（grill-with-docs，2026-10-15）

- 本轮优先补全 Codex Hook 的新增、编辑与删除。
- 定义维护只覆盖当前 Codex home 的用户配置；插件定义保持只读，沿用既有查看与启停能力，不纳入项目定义维护。
- 创建和编辑使用结构化表单，原始配置只读；不提供直接编辑整份 JSON/TOML 的入口。
- 同时支持 `command` 与 `mcp_tool` 两种 Hook 类型。
- 已有定义在原文件维护；新增沿用已有单一格式，首次默认 `hooks.json`，JSON/TOML 双来源并存时由用户明确选择保存位置。不自动迁移定义。
- 总开关关闭时仍可查看、新增、编辑、删除用户定义，并说明当前未启用；保存不自动打开总开关。定义清单与 Codex 的原生配置状态分开表达。
- 信任审查继续由 Codex CLI `/hooks` 或桌面 App 完成。本工具保存定义后重读原生状态，需要审查时提供指引；编辑、删除不要求定义先获得信任，不自行授予信任。
- 每次只维护所选 Hook 的定义。共享匹配条件时只改变目标条目，必要时拆组。
- 新建默认选择启用，表单允许改为禁用后保存；定义保存、启用选择、信任与实际会话生效分别表达。
- CLI 缺失、不兼容或无法读取原生状态时，可展示能读取的用户定义与原因，但暂停新增、编辑和删除。正常关闭总开关不属于这类异常，按 Q6 支持维护。
- 编辑或删除造成其他条目身份变化时，保留其定义和启用选择；身份变化的条目重新在 Codex 审查。保存前展示受影响范围，不把旧信任复制给新身份；无法可靠定位或保护状态时拒绝操作并说明原因。

术语沿用 [CONTEXT.md](../../CONTEXT.md)；上一轮需求与验证见 [Hooks 管理](../codex-hooks-management/PRD.md)。

## 现有边界

- 现有实现通过原生清单展示当前 Codex home 的用户与已启用插件来源，只保存单条 Hook 的用户级启用设置。
- 创建、编辑和删除定义超出 [ADR-0013](../../docs/adr/0013-codex-hooks-use-native-inventory-and-user-state.md) 的首版范围；本轮需要明确如何扩展该边界。
- 现有信任审查由 Codex 原生界面承担。定义变更可能影响信任，新功能不能把配置保存等同于获得信任或已在会话中生效。

## 已核实的官方事实

- 用户定义支持 `hooks.json` 和 `config.toml` 内联 `[hooks]`；两种来源会累加而非覆盖，同层并存会产生警告，官方建议同一层使用一种表示。
- 定义层级为事件、匹配组、组内多个处理程序。直接修改匹配组的 `matcher` 会改变同组全部处理程序的触发条件，因此单条编辑需要明确操作粒度。
- 当前支持 `command` 与 `mcp_tool`；`prompt`、`agent` 只解析后跳过。事件和类型存在组合限制，例如 `mcp_tool` 不支持 `SessionEnd`。
- 信任绑定当前定义的 hash。官方未说明完整身份算法、字段变化与 hash 的对应关系、删除后的状态清理或身份迁移契约。
- App Server 文档提供 `hooks/list`、通用配置写入和文件写入接口，未文档化 Hook 定义专用的新增、编辑、删除接口；不能把通用写入能力视为逐条定义维护和信任迁移的保证。

来源：[Hooks](https://developers.openai.com/codex/hooks)、[App Server](https://developers.openai.com/codex/app-server)，2026-10-15 实际获取核实。

## 已确认的整体方案

### 操作与展示

- 沿用 Codex → Hooks 页面，提供新增、单条编辑与删除。列表区分用户定义与只读插件定义，单独展示启用选择、信任与总开关限制；不把文件存在当作已加载。
- 创建及编辑表单包含事件、类型、匹配条件、命令或 MCP server/tool/input，并提供适用于该类型的高级字段，如超时、状态提示、Windows 命令、异步执行及上下文限制。按当前已核实的事件/类型组合校验；保留字段原本未指定的含义，不无条件写入全部默认值。
- 原始配置只读，明确展示来源路径。用户 JSON/TOML 同时存在时呈现原生警告，不静默合并、去重或迁移。
- 编辑保留所选 Hook 原有的启用选择；新增使用表单明确选择，不能继承该位置残留的启用或信任记录。定义变化后的信任以原生审查为准。
- 保存前展示定义变更和需重新审查的条目；删除单独确认事件、内容和来源。删除只移除目标定义及为本次身份变化必须维护的状态，不删除引用的脚本或其他资产。
- 提交后重读来源与原生状态，区分保存结果和读取结果；失败保留用户表单。已有会话是否即时生效仍不承诺，提示在新会话中验证。

### 保留与失败边界

- 原位修改目标定义，保留未编辑定义、未知字段、无关配置及其注释。无法解析或无法安全维护的结构只读，不用表单重建整份配置。
- 同组拆分与删除不得意外改变其他条目的定义或启用选择。只清理/撤销能够明确归属于此次操作的状态，不自动授予或迁移信任，不进行全局孤儿状态清理。
- 外部修改检测覆盖完整来源文件和相关用户状态，不能只比较原生 `currentHash`。检测到变更时中止旧提交、保留表单并要求基于新内容重新确认，不自动覆盖重试。
- JSON 定义与 TOML 状态不宣称跨文件原子提交。写入前需有可验证的执行与失败处理顺序；不能保证影响范围或状态保护时拒绝操作。若已发生部分保存，明确报告实际变更与恢复步骤，禁止将部分保存显示为完整成功。
- 已验证 CLI 0.162.1 不是最低版本或跨版本保证。定义读写、身份映射与状态维护能力须独立验证；不得把未经核实的 key 格式推广到其他版本。
- 本轮只做配置结构与字段校验，不执行命令或 MCP 工具，不增加触发历史、运行排障、总开关操作、项目维护、插件定义编辑或批量管理。

### 验收场景

| 场景 | 预期 |
| --- | --- |
| 首次创建用户 command Hook | 默认写入 hooks.json，表单可选择启用/禁用；显示保存、信任和生效提示 |
| 仅有 TOML 定义时创建 | 沿用 TOML，不额外创建 JSON 定义来源 |
| JSON/TOML 均有定义 | 原位编辑；新建明确选择位置，保留双来源提示 |
| 创建/编辑 MCP Hook | 保留完整 input；非法 JSON、事件或字段组合不可保存 |
| 修改 Windows 命令、默认值或高级字段 | 不从清单摘要重建定义，不丢失原始字段或忽略原文变更 |
| 总开关关闭 | 用户定义仍可维护，清楚标记关闭，不改持久总开关 |
| CLI 缺失、不兼容或原生读取失败 | 展示可读定义与原因，暂停写入 |
| 用户定义尚未信任 | 可编辑和删除；不在本工具授予信任 |
| 修改共享组内一条的匹配条件 | 仅目标定义改变；其他条目启用选择保持，身份变化者明确需重新审查 |
| 删除前项或整组 | 其他定义与启用选择不变；不能让相同定义的后项继承错误的可信启用状态 |
| 新建复用历史位置 | 不继承该位置的历史启用或信任记录 |
| 外部修改、未知结构、无法确定关联 | 不覆盖外部变更或丢字段，不进行无法证明影响范围的写入 |
| 保存中途失败或保存后重读失败 | 分别报告实际结果；保留表单，旧清单不可继续提交 |
| 删除确认取消 | 零写入；引用脚本及无关配置始终保留 |

身份与状态实验见[事实核查](RESEARCH.md)。Q1–Q12 已全部确认，本轮设计可作为实现依据。
