# Codex 插件管理

Status: done

## 已确认的方向（grill-with-docs，2026-10-14）

- 首版聚焦 Codex plugin 管理。Claude Code 与独立 skill 管理留待后续讨论。
- 用户：个人开发者，管理本机 Codex。
- 首要价值：查看本机已安装插件及状态，并启用／禁用。
- 产品承载：加入当前「包管理器控制中心」，作为独立功能入口。
- 首版操作：只做查看、启用与禁用；发现、安装、更新和卸载留待后续。
- 目标客户端：同时面向本机 Codex CLI 与桌面 App；管理的是所选范围内的本地插件配置，不承诺另一个运行中客户端的实时状态。
- 配置作用域：只管理用户默认配置，不扫描或修改项目配置；页面提示项目设置可能覆盖用户默认值。
- 环境范围：只管理当前环境解析到的一份 Codex home，优先 `CODEX_HOME`，否则 `~/.codex`；展示实际目录，不提供多环境切换或目录选择器。
- 状态含义：只展示可核实的安装与配置状态，无法确认时显示未知；不检测当前会话加载情况、MCP 连接或认证状态。
- 生效反馈：启停成功表示“配置已保存”，提示在新会话中验证，不承诺现有会话立即生效。
- CLI 依赖：首版要求本机存在支持插件清单的 Codex CLI，包括平常只使用桌面 App 的用户；缺失或版本不兼容需要明确说明，不能显示为无插件。
- 展示内容：列表包含名称、版本、所属插件市场与用户默认启用设置；详情补充来源和路径。首版不展开 skills、MCP、hooks 等内部能力。
- 操作粒度：一次只启用或禁用一个插件，确认目标与变更后保存，不支持批量启停；失败时明确说明结果。
- 刷新：首次进入读取，提供手动刷新，操作后重读；不自动跟随外部修改。保存前若发现目标设置已改变，刷新并重新确认。
- 未显式设置：配置可正常解析、但目标插件没有 `enabled` 时，显示“未知（用户未显式设置）”，允许选择“设为启用／设为禁用”，确认后保存；不新增恢复继承操作。
- 配置异常：读取或解析失败时说明原因并禁止修改，不覆盖原配置。

术语以 [CONTEXT.md](../../CONTEXT.md) 中的「Codex 插件」「插件市场」「用户默认启用设置」为准。

## 接入边界

- 清单取自官方 `codex plugin list --json` 的 `installed`，不扫描缓存来推断安装，不用用户配置项充当完整清单，不请求未安装插件目录。
- 清单读取与执行前复核使用同一个 Codex home，在项目外目录调用 CLI，避免引入当前工作项目的配置。
- 安装身份保留官方 `pluginId`；插件名与所属市场共同区分同名插件，不能按显示名称合并或操作。
- 用户默认启用设置来自当前 Codex home 的用户配置。CLI 清单中的 `enabled` 缺少配置来源层，不能直接作为用户显式设置展示，也不能据此宣称当前项目或会话已生效。
- 启停基于保存前最新可读的用户配置，只修改目标插件的 `enabled`，保留其他设置和注释；无关项的外部修改也不能被旧副本覆盖。不修改项目配置、插件安装内容或来源文件。
- 本地插件配置可被使用同一 home 的 CLI 与桌面 App 读取。App 的工作区托管插件不纳入此入口，不根据另一个客户端的窗口或会话推断状态。
- 只确认过本机 `codex-cli 0.162.1` 具备清单能力，尚无最低版本依据；兼容性按所需能力判断，不把本机版本当作最低版本声明。

接入依据与取舍见 [ADR-0011](../../docs/adr/0011-codex-plugins-use-cli-inventory-and-user-config.md)。

## 页面与操作流程

1. 从当前应用的独立插件管理入口进入，展示所管理的 Codex home、用户默认配置范围及项目覆盖提示。
2. 读取已安装清单及用户默认启用设置；读取成功且清单为空时展示空状态，CLI 缺失、不兼容或读取失败分别展示原因。
3. 列表按已确认字段展示插件，详情提供来源与路径；可选元数据缺失时如实标注，不编造版本或位置。
4. 用户选定一个插件的目标设置后，确认对象、所属市场、启用或禁用的变更，以及只修改用户默认设置的影响范围。
5. 保存前重新核实插件仍在已安装清单中，并复核目标设置；目标消失或设置已变更时不按旧确认写入。用户取消确认则不写入。
6. 保存后重新读取并展示结果。配置已保存但随后清单刷新失败时，分别报告保存与刷新结果，不把它描述为当前会话已经生效。

## 验收场景

| 场景 | 预期行为 |
| --- | --- |
| CLI 可用，清单读取成功但无已安装插件 | 展示空状态，不提供安装操作 |
| CLI 缺失、版本不兼容或清单读取失败 | 说明具体原因，不伪装为空清单 |
| 不同市场里存在同名插件 | 分别展示，确认和写入均指向明确的插件身份 |
| 用户显式启用，某个项目另有覆盖 | 显示用户默认设置与覆盖提示，不读取或改写该项目配置 |
| 用户配置未显式设置 `enabled` | 显示“未知（用户未显式设置）”，允许明确选择设为启用或禁用并确认；不从 CLI 有效值或缓存推断用户选择 |
| 用户配置无法读取或解析 | 如实说明状态未知及原因，不覆写无法理解的配置 |
| 用户取消确认 | 配置不变 |
| 确认后目标插件消失或目标设置被外部修改 | 中止旧操作，刷新并要求用户重新选择或确认 |
| 正常启用或禁用一个插件 | 只保存该插件的用户默认设置，其他配置保持不变，随后重读 |
| 保存失败或保存后的刷新失败 | 区分两个阶段的实际结果，不能仅凭点击结果翻转显示状态 |
| 在其他客户端中修改配置 | 手动刷新后反映变化；操作前复核仍然执行 |
| CLI 与桌面 App 使用不同 home | 只管理页面展示的那份配置，不承诺影响另一份环境 |

## 已核实的背景

- 需求调研时，产品是面向 macOS 开发者的桌面应用，已有 Codex 会话记录能力，尚无插件管理能力。产品定位见 [PRODUCT.md](../../PRODUCT.md)，领域词汇位于 [CONTEXT.md](../../CONTEXT.md)。
- 官方 Plugin 是可组合 skills、MCP servers、hooks 等内容的安装与分发单元；插件的安装状态、启用配置和组件实际可用性不能视为同一状态。见 [Plugins](https://developers.openai.com/codex/plugins.md)。
- 本机只读验证：`codex-cli 0.162.1` 支持 `codex plugin list --json`，返回 `installed` 与 `available`；已安装项包含身份、版本、来源和启用信息。本机帮助没有独立插件启停子命令，通用 `--enable/--disable` 作用于 feature flags，不能当作插件启停。见 [CLI reference](https://developers.openai.com/codex/cli/reference.md)。
- 官方持久化启停使用 `config.toml` 的 `[plugins."plugin-name@marketplace-name"].enabled`。可信项目配置和命令行覆盖可能改变用户默认设置；列表中的 `enabled` 没有配置来源层信息，不能仅凭该字段判断用户默认值。见 [插件配置](https://developers.openai.com/plugins/build/plugins.md#enable-or-disable-a-plugin-for-a-repo) 与 [配置优先级](https://developers.openai.com/codex/config-file/config-basic.md#configuration-precedence)。
- 官方明确安装后需新建 chat/session；启停对现有会话是否即时生效尚未证实。实现验证中的配置写入均使用临时测试目录，未修改用户实际配置。
- 官方明确本地插件的 `enabled` 配置适用于 CLI 和桌面 App；工作区托管插件采用另一套管理状态。共享本地配置以两个客户端实际使用同一 Codex home 为前提，本次未验证运行中 App 的目录或版本。见 [插件配置](https://developers.openai.com/plugins/build/plugins.md#enable-or-disable-a-plugin-for-a-repo)。
- 官方没有提供从缓存目录完整重建已安装清单的契约；配置项也不等同于安装登记。当前未找到无 CLI 或旧 CLI 下等价可靠的清单回退。`plugin list` 的启用值不包含配置来源层，用户配置缺失 `enabled` 时也没有已核实的统一缺省值，不能自行当作开启或关闭。
