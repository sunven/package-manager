# VS Code 工作区存储移除

状态：已实现并验证（2026-10-23 完成人工端到端验证）。

## 目标

在现有「VS Code 占用」观察页面上，允许用户把无法关联到可用项目的工作区存储记录整体移入废纸篓，回收 `workspaceStorage` 占用，同时避免误删仍在使用的编辑器状态。

术语以 [CONTEXT.md](../../CONTEXT.md) 中的「工作区存储」「可移除工作区存储记录」「VS Code 工作区存储移除」「目录占用」为准。本文用「移除」描述这个操作，不用「清理」，因为它处理的是编辑器状态和扩展数据，不是可重建缓存。

## 已确认的需求

- 移除对象是清单中每条记录对应的整个 `workspaceStorage/<id>` 目录，包含 `state.vscdb` 与扩展数据；不涉及 `globalStorage`、`Cache` 或其他 VS Code 数据。
- 只有「路径不存在」和「未识别工作区」两类记录可移除；「路径存在」「远程工作区」「路径无法访问」不可移除。
- 可移除资格由后端在扫描时给出（`removable` 和不可移除原因），前端不只按状态过滤；符号链接、非普通目录等前端看不出的情况必须排除。
- 移除通过系统废纸篓完成，复用现有 `move_path_to_trash`；清空废纸篓前可恢复，磁盘空间不会立即释放。
- 要求稳定版 VS Code 未运行。运行中或无法确认进程状态时禁用移除入口；执行开始前和每一项前重新检测，检测到启动就停止剩余项。
- 页面不再标记为「只读」，改为「可移除」；保留现有范围说明和四张汇总卡片，不新增「可移除」卡片。
- 只在现有页面内增加复选框和批量工具栏，不做单行垃圾桶按钮；「全选可移除」只选当前搜索结果中可见且可移除的记录。
- 确认框列出完整目标、合计占用（统计不完整时带 `≥`）和风险说明；执行中显示流式进度，不支持中途取消，也不允许关闭对话框。
- 单条失败不阻止后续；执行结束后自动重扫，结果保留「已移入 / 跳过 / 失败」与逐条原因；重扫失败单独提示。
- 不写入维护记录，不提供本工具层面的撤销（恢复依赖系统废纸篓），不提供永久删除、清空废纸篓、VS Code Insiders、其他 VS Code 分支或自选目录。
- 移除不改变现有的目录占用口径和汇总卡片含义。

## 交互流程

1. 页面扫描 `workspaceStorage`，后端为每条记录计算 `removable` 与不可移除原因；编辑器状态单独读取。
2. 只有可移除记录显示可用复选框；工具栏提供「全选可移除」「取消选择」「移除 N 项」。
3. VS Code 运行中或状态未知时，页面显示横幅并禁用「移除 N 项」。
4. 点击移除时再检测一次编辑器状态；不是「已退出」就不打开确认框。
5. 确认框冻结当前选中的工作区记录，显示条数、合计占用、完整目标列表和风险说明。
6. 确认后把记录 ID 列表交给后端；后端逐条重新判定，移动成功、跳过、失败都进入结果。
7. 执行中通过 Tauri 每次调用 Channel 报告进度；对话框不可取消、不可关闭。
8. 执行结束后先展示结果，再自动重扫；重扫结果与操作结果分别呈现。

## 资格与执行时复核

- 扫描时：`projectStatus` 为 `Missing` 或 `Unknown`，且目标是 `workspaceStorage` 下非符号链接的普通目录 → 可移除；其余记录不可移除，并给出原因。
- 执行时逐条重新读取目标目录和 `workspace.json`：
  - 目标消失、变成符号链接或非目录 → 跳过。
  - 项目状态变成 `Available`、`Remote` 或 `Unavailable` → 跳过（例如外接磁盘重新挂载、项目被移回）。
  - 项目状态仍是 `Missing` 或 `Unknown` → 可以移入废纸篓。
- 跳过必须带原因，不能静默失败；单个目标失败不阻止后续目标。
- 执行开始前检测 VS Code；执行过程中每一项前再检测；检测到运行或无法确认时停止剩余项，并在结果中说明。
- 扫描失败或正在扫描时禁用移除入口；`Partial` 扫描允许移除，但确认框中的占用显示为下限。

## 确认框文案要点

- 标题：确认移入废纸篓。
- 说明：将把 N 条工作区存储记录移入废纸篓；清空废纸篓前可恢复，移入废纸篓不代表磁盘空间立即释放。
- 风险：「路径不存在」可能是外接磁盘未挂载或项目被移动；「未识别」记录可能仍包含扩展数据。
- 复核：执行时会重新检查，项目路径恢复或记录变化的目标会被跳过。
- 按钮：取消 / 移入废纸篓 N 项；执行中改为「正在移入废纸篓」并禁用。

## 异常与边界

- `workspaceStorage` 根目录不存在：保持现有「未发现」状态，不提供移除。
- 根目录不可读、部分记录不可读：保留现有 `Partial` 展示；可移除记录仍可尝试，执行时再次判定。
- 目标在确认后消失：跳过，原因「记录已不存在」。
- 外接磁盘重新挂载、项目路径恢复：跳过，原因「项目路径已恢复」。
- VS Code 在确认后启动：停止剩余项，结果说明「VS Code 已启动，剩余 N 项未处理」。
- 移入废纸篓失败：该项标记失败并继续；结果给出错误信息。
- 重扫失败：保留操作结果，单独显示刷新失败。
- 页面切换：扫描结果、操作状态和结果保留，与现有 VS Code 扫描及会话记录操作一致。
