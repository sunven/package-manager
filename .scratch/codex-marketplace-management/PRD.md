# Codex 市场源管理

Status: done

## 已确认的方向（grill-with-docs，2026-10-14）

- 首版聚焦市场源管理：查看已添加的市场、添加来源、刷新市场目录、移除市场。
- 浏览市场中的可用插件，以及独立的插件安装、更新、卸载操作，不纳入本次功能；官方市场刷新可能连带同步已配置插件，按下述已确认边界处理。
- 页面入口：在现有「Codex 插件」页内分为「已安装／市场源」两个页签，沿用页面展示的当前 Codex home。
- 刷新方式：用户手动逐个调用官方市场刷新；接受 Codex 官方同步行为，不承诺只更新市场目录或保持所有已安装插件不变。首版不提供自动刷新或刷新全部。
- 添加来源：支持 Git 仓库与本地市场根目录。Git 输入接受仓库简写或 URL，本地来源选择市场根目录；首版不提供自定义分支或稀疏检出选项。
- 可维护范围：展示 CLI 可见的全部市场，但仅允许维护能明确确认属于当前 Codex home 用户配置的市场源；默认、受管理或无法确认归属的来源只读，并显示原因。
- 私有 Git 认证：使用本机 Git 已配置的 SSH 或凭据；应用不新增登录、密钥或令牌保存功能。认证失败时说明原因，由用户完成本机认证后重试。
- 列表内容：市场名称、来源类型、来源地址或路径、可执行操作及受限原因；详情展示实际本地目录。首版不增加插件数量或占用统计。
- 清单读取：首次进入、用户手动重读及操作后读取最新结果；不定时轮询。重读本机清单与从 Git 来源刷新目录是不同的操作。
- 移除市场：存在已安装插件时仍允许移除，确认目标与影响后只调用官方市场移除；应用不追加卸载插件、清理插件启用设置或删除原始来源目录的操作。Git 市场的本地副本会由官方命令移除。
- 重复与冲突：相同来源重复添加时提示「已存在」；同名但来源不同则拒绝替换，用户需先明确移除旧来源再添加。不自动串联移除与添加。
- 操作确认：添加时在表单确认来源；刷新和移除前确认目标及影响。维护操作逐个执行，用户取消则不执行。
- 外部变更：执行前重新核实当前 home、目标来源与可维护资格；来源被其他客户端改动、目标消失或无法核实时中止旧操作，重新读取后由用户重新选择或确认。
- 结果反馈：命令执行结果与后续清单读取结果分别报告，不能把刷新失败描述为操作未执行，也不能仅凭命令退出就宣称全部成功。

术语以 [CONTEXT.md](../../CONTEXT.md) 中的「Codex 插件」「插件市场」「市场源」「市场本地副本」为准。

## 现有背景

- 当前应用已提供独立的「Codex 插件」入口，支持查看已安装插件、查看来源详情，以及单个用户默认启用设置的修改。
- [ADR-0011](../../docs/adr/0011-codex-plugins-use-cli-inventory-and-user-config.md) 规定既有插件清单来自官方 CLI，启停修改当前 Codex home 的用户默认设置。本次新增市场源维护能力，沿用当前 home 和用户范围，不改变既有插件清单与启停的接入边界。
- 现有实现只消费插件清单中的 `installed`，没有独立的市场清单或市场源管理能力。

## 已核实的接入事实

- 官方 CLI 提供独立的 `codex plugin marketplace list --json`。应以市场清单观察市场，不能把已安装插件按市场分组当作完整市场清单，因为没有已安装插件的市场也需要展示。
- 官方市场命令包括 `add`、`list`、`remove`、`upgrade`；`upgrade` 用于刷新已配置的 Git 市场快照，与重新读取本机市场清单不同。
- `add` 支持本地市场根目录及 Git 来源，包括 `owner/repo`、HTTP/HTTPS Git URL、SSH Git URL；还支持 ref 与 sparse 选项。本地市场根目录需包含 `.agents/plugins/marketplace.json`，不是任意 JSON 文件位置。首版来源范围已在 Q4 确认。
- `list --json` 包含 `marketplaces`，条目有 `name`、`root` 和可选的 `marketplaceSource`；本机观察到来源包含 `sourceType` 与 `source`。清单没有配置层级、是否默认市场或操作权限字段，不能仅凭清单判断哪些市场是用户添加、可修改的来源。
- `upgrade <MARKETPLACE_NAME>` 针对指定 Git 市场；省略名称会处理全部已配置 Git 市场。本地市场不属于同一种 Git 刷新操作。
- 本机只读核实版本为 `codex-cli 0.162.1`；这不是已证实的最低支持版本。
- 已读取的官方文档和本机帮助未说明移除市场是否影响已安装插件；下面的独立临时环境测试补充了本机版本行为，不能据此作跨版本保证。
- 官方配置参考在 `plugins.<plugin>.enabled` 下说明：市场刷新可能安装或刷新已配置插件，即使插件被禁用。说明本身未明确点名 CLI `marketplace upgrade`，下述临时环境实验进一步验证了本机命令确实可能改变已禁用插件内容。Q3 已确认接受官方同步语义，决策见 [ADR-0012](../../docs/adr/0012-marketplace-refresh-follows-codex-sync-semantics.md)。
- 独立临时 Codex home 中的本机实验：添加相同本地市场源再次成功并返回 `alreadyAdded: true`；不同根目录、相同市场名的添加失败，CLI 要求先移除。移除包含一个测试插件的本地市场后，市场配置消失，已安装插件缓存、插件启用配置及原始来源目录保留。该结论限本机 0.162.1 的测试场景，不等同于跨版本官方契约。
- 独立临时 Git 实验：以仅对子进程生效的 Git URL 重写连接自建本地仓库、只允许 `file` 协议；`marketplace upgrade <name> --json` 确实刷新了已安装测试插件的缓存内容，即使该插件设置为 `enabled: false`，且保留该禁用设置。移除 Git 市场后测试插件缓存、启用设置及原始 Git 仓库保留。
- Git 市场移除会删除其市场本地副本；本地市场移除保留其原始市场目录。市场本地副本和已安装插件缓存不能混为同一对象。
- 通过命令行配置注入的市场同样带有 `marketplaceSource`，但 CLI 拒绝从用户层移除。人工配置键也可能与清单中的市场名不同，因此不能仅按显示名称匹配用户配置。完整观察与验证限制见 [接入调查](CLI-INVESTIGATION.md)。

依据：[CLI marketplace reference](https://developers.openai.com/codex/cli/reference#codex-plugin-marketplace)、[Add a marketplace from the CLI](https://developers.openai.com/plugins/build/plugins#add-a-marketplace-from-the-cli)、[配置参考](https://developers.openai.com/codex/config-reference)（官方重定向至 [Config reference](https://learn.chatgpt.com/docs/config-file/config-reference)）。

## 接入与兼容性边界

- 延续现有 CLI 依赖：要求本机可调用具备所需市场命令的 Codex CLI；按实际能力判断兼容性，不把本机验证版本当作最低版本。缺失、不兼容或读取失败应明确说明，不展示为正常空清单。
- 市场清单取自官方 `marketplace list --json`。维护委托官方 `add`、指定目标的 `upgrade` 和 `remove`；应用不自行改写市场配置、拉取 Git 仓库或删除市场目录来模拟这些命令。
- 读取、确认和执行使用同一个当前 Codex home，并沿用现有项目外工作目录，避免意外引入工作项目配置。不新增多 home 切换、项目配置管理或桌面 App 工作区托管市场管理。
- 用户配置用于核实市场归属，不能充当完整市场清单。保留官方来源信息和实际操作身份；不能只按显示名称匹配，也不能把有 `marketplaceSource` 的行都视为可写。用户配置无法读取或解析、归属有歧义或官方拒绝操作时，不尝试绕过限制。
- 实现通过 CLI 自带 `app-server` 的只读 `config/read` 获取字段归属，与用户配置、来源地址及可选 ref／sparse 设置核对。无法提供归属信息时市场只读，不将完整配置发送至前端。
- Git 市场提供指定市场的官方刷新；本地市场通过重新读取反映本机内容，不提供 Git 刷新操作。默认来源、受管理来源及归属未知来源保持只读。
- 添加来源交由官方 CLI 验证并返回最终身份；无效目录、网络或认证失败、同名冲突按实际结果反馈，不由应用自动覆盖或替换来源。
- 私有来源依赖可在应用进程环境中使用的本机 Git 认证；需要用户补充认证时结束本次操作并说明原因，不在应用内索取凭据或无限等待交互。
- 解析官方结果中的错误信息及部分失败，不能只检查进程退出码。失败后不假定完全回滚；通过重新读取呈现可核实状态，应用不自动追加补偿删除或替换。
- 操作后重读市场清单；可能改变插件内容的市场同步还应使「已安装」页的数据失效并在显示时重新读取。读取失败时保留上次结果并明确其已过期，不误报为空清单或当前有效结果。

## 页面与操作流程

1. 在「Codex 插件」入口提供「已安装／市场源」两个页签，共用当前 Codex home 的范围说明；既有插件启停能力保留。
2. 进入「市场源」时读取市场清单和可维护资格，展示已确认字段。缺失的来源信息如实标记未知，只读原因可见；清单成功读取且为空时显示添加入口。
3. 「重新读取」只读取当前本机清单；指定 Git 市场的「刷新市场」执行官方同步。文案明确区分两者，本地来源不提供 Git 同步动作。
4. 添加时选择 Git 来源或本地市场目录，核对输入后提交；成功后读取官方返回的市场身份。重复来源显示已存在，同名异源给出冲突原因。
5. 刷新时确认市场名称、来源及可能同步已配置插件的影响；禁用插件也可能被同步，刷新不表示插件已在现有会话中生效。
6. 移除时确认市场名称、来源及影响；说明 Git 市场本地副本会被移除。应用只执行官方市场移除，不追加插件卸载或原始来源删除。
7. 刷新与移除执行前重核目标身份、来源和资格。发现外部变更时中止旧操作并重新读取，用户重新选择或确认后才能继续。
8. 维护操作逐个执行并显示进度及结果；执行结果与重读结果分别呈现。成功后重读失败不能诱导用户以为操作未执行。

## 验收场景

| 场景 | 预期行为 |
| --- | --- |
| 市场没有任何已安装插件 | 仍出现在独立市场清单中 |
| CLI 缺失、不兼容或市场清单读取失败 | 说明原因，不伪装为空清单，也不影响既有能力的独立判断 |
| 成功读取且没有市场 | 显示空状态和添加入口 |
| 默认、受管理或归属未知的来源 | 展示可获取信息及只读原因，不提供维护动作 |
| 用户配置损坏或市场名称与配置键不一致 | 不按显示名称猜测身份；无法明确关联时只读 |
| 添加有效 Git 来源或本地市场根目录 | 官方命令成功后展示实际身份、来源类型和位置 |
| 本地来源不是有效市场目录 | 显示校验失败原因，不虚构添加成功 |
| 私有 Git 来源认证不可用 | 结束本次操作并说明本机认证要求；应用不新增凭据保存 |
| 再次添加相同来源 | 提示已存在，不生成重复行 |
| 同名市场来自不同来源 | 拒绝替换，不自动移除旧来源 |
| 用户只重新读取清单 | 不调用官方 Git 市场刷新命令 |
| 本地市场内容被外部修改 | 重新读取反映可核实变化，不提供 Git 刷新 |
| 刷新 Git 市场且其中有已禁用插件 | 确认文案说明可能同步插件内容；保留实际启用设置，不承诺当前会话生效 |
| 市场含已安装插件，用户确认移除 | 仍允许官方移除；应用不追加插件卸载、插件设置清理或原始来源删除 |
| 移除 Git 市场 | 官方命令移除市场本地副本，结果与界面如实反映；不把副本当成已安装插件 |
| 用户取消添加、刷新或移除 | 不执行对应维护命令 |
| 确认后 home、来源或可维护资格改变 | 中止旧操作，重新读取并要求重新选择或确认 |
| CLI 拒绝来源归属或返回部分失败 | 展示实际错误，不绕过官方限制，不宣称全部成功或已完全回滚 |
| 命令成功但随后清单读取失败 | 分别显示已完成的命令结果与读取失败，上次清单标记过期 |
| 市场刷新改变了插件内容 | 已安装页再次显示时重新读取，避免继续展示旧插件数据 |

「Codex 插件」入口内提供「已安装／市场源」页签：市场源列表展示名称、类型、来源与只读原因，支持 Git 或本地市场根目录的添加、逐个 Git 刷新与官方移除。可维护资格要求官方来源、用户配置与 `app-server` 只读 `config/read` 归属三者一致；默认、受管理与归属不明的市场保持只读。执行前复核目标与资格，命令结果与重读结果分别报告。实现文件、测试结果、界面评审证据及验证边界见 [验证记录](VERIFICATION.md)。
