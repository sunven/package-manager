# Node 依赖目录使用扫描会话护栏删除

ADR-0001 将委托清理设为默认，避免本工具根据推导的管理器缓存路径删除用户数据；但 `node_modules` 是项目派生数据，且 npm、pnpm、Yarn 与 Bun 没有一个通用的整目录清理命令。我们决定将 Node 依赖目录记为护栏删除例外：后端只接受当前扫描会话中的候选 ID，并在执行前重新断言路径仍位于已授权扫描根目录内、basename 为 `node_modules`、同级 `package.json` 是常规文件，且目标是非符号链接目录，才递归删除。候选内部允许符号链接或 Windows junction，但测量与删除只能处理链接条目本身、不得跟随其目标；无法保证该语义的平台必须拒绝清理。测量时若发现任一非链接子目录跨越设备或卷边界，该候选不可清理；执行前必须再次检查，不得进入真实挂载点。清理是不进入废纸篓的永久删除，清理后不自动重新安装依赖。

## Consequences

- 前端不能提交任意路径；重扫使旧候选失效，执行时身份检查失败必须拒绝删除。
- 候选内部的链接与跨文件系统目录都不能扩大护栏删除的权限边界；无法证明边界未被跨越时必须拒绝。
- 该例外不放宽管理器缓存的委托清理原则，也不允许为了提高覆盖率而删除未由扫描会话登记的 `node_modules`。
