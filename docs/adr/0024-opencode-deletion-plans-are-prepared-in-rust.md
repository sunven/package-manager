# OpenCode 删除计划由 Rust 准备并执行

OpenCode 删除的资格规则、级联范围与批量执行现在由 Rust 拥有；`prepare` 读取已登记服务，冻结一份带 `planId` 的删除计划，`commit` 只接受该 `planId` 并重新核对后执行。前端只展示 prepared plan，不再用 TypeScript 重新计算 roots、后代或年龄资格。

## Considered Options

- 保留前端计划 + 后端复核：同一套 roots/级联/年龄规则存在两份实现，前端预览可能与后端预检不一致。否决。
- 无状态计划回传：`prepare` 返回整份计划，`commit` 再把计划传回。少一个后端槽位，但确认对象可以被前端改写，核对边界更宽。否决。
- 后端单槽计划 + `planId`：采纳；与现有 Hook 定义的 prepare/commit 形态一致。

## Consequences

- 单条、明确多选和按年龄共用 prepare/commit，但资格差异保留：单条只预检根会话，明确多选预检所有受影响会话，按年龄核对冻结范围。
- 批量执行器只保留一份：顺序删除、首个失败后停止、逐项报告结果。
- 提交结果携带实际完成 ID（含级联后代），前端不再计算完成范围。
- 前端需要在计划准备期间显示准备状态，并把准备错误与读取错误分开。
- ADR-0021 与 ADR-0022 继续有效；计划仍然不是服务端原子性保证。
