# VS Code 工作区存储移除只处理不可用记录并移入废纸篓

VS Code 工作区存储包含编辑器状态和扩展数据，不能当作可重建缓存。移除能力只对项目路径不存在或无法识别的记录开放，且目标必须是 `workspaceStorage` 下非符号链接的普通目录。确认后执行时逐条重新读取项目和目录；项目路径恢复（例如外接磁盘重新挂载）、记录消失或目标变成符号链接的，留在原处。移除通过系统废纸篓完成，清空废纸篓前可恢复。执行前要求稳定版 VS Code 未运行，执行中每一项前再次检测；检测到运行或无法确认时停止剩余项。

## Considered Options

- 允许用户显式移除任意记录：页面没有最近打开时间，用户无法判断「路径存在」的记录是否仍在使用；删除活动工作区的存储可能破坏扩展状态。否决。
- 永久删除：工作区存储不是可重建缓存，永久删除无法恢复；与 ADR-0005 对非可重建数据的要求不一致。否决。
- 在 VS Code 运行时执行，或只按 `lsof` 跳过被占用记录：VS Code 空闲时不一定持有文件句柄，扩展宿主可能在退出时回写状态；`lsof` 不能证明安全。否决。
- 由前端按 `projectStatus` 判定资格：前端看不到符号链接、非普通目录和不可读条目，也无法在执行时复核项目路径是否恢复。否决。
- 后端给出可移除资格，执行时逐条复核，要求编辑器退出且移入废纸篓：采纳。

## Consequences

- 确认条数可以大于实际移入条数；项目路径恢复或记录变化的目标会被跳过并说明原因。
- 「未识别工作区」也可移除，但它可能仍包含扩展数据；确认框必须提示这一点。
- 页面需要展示编辑器状态；VS Code 运行或状态未知时不能发起移除。
- 移除不立即释放磁盘空间；汇总数字的下降表示记录已离开原目录，不表示物理空间已回收。
- 不新增维护记录；恢复依赖系统废纸篓。
- 沿用 ADR-0005（非可重建数据进废纸篓）和 ADR-0007（执行时重判），并把「编辑器退出」作为 VS Code 特有的前置条件。
