# Claude 技能采用定义清单，调用控制使用原生名称设置

Claude 技能管理需要包含禁用项、插件技能与旧版命令，而当前已核实的 SDK 会话清单存在明确遗漏，本轮未发现与 Codex `skills/list` 等价的完整管理接口。Q5 确认使用当前用户范围内可读取的定义清单，标明来源、读取问题及相关设置；接受它不代表原生完整发现或会话加载结果，不通过不完整的可调用清单推断技能不存在。

Q7 确认调用控制采用 Claude 原生 `skillOverrides` 四态及移除用户覆盖。它按名称生效，用户设置可能影响多个项目的同名技能，且能被更高优先级配置覆盖；不将其包装成与 Codex 按技能路径启停等价的文件开关。插件技能随所属插件管理，不引入第二套私有停用存储，也不通过改写共享技能内容来实现停用。

Q6 确认文件维护仍以本应用持有的安装副本为界：原有普通目录、共享目录与外部链接不接管更新和卸载，插件及同步技能交原来源维护。原生名称设置、定义来源及安装副本身份分别判断，发现一个定义不能授予文件维护资格。这延续 ADR-0019 的归属边界，但不把 Codex 的清单与启停契约套到 Claude。

Q9–Q11 进一步确认复制安装、更新保留调用设置和本地修改时停止。卸载只将应用持有的副本移入废纸篓，保留按名称的用户设置；新装也不强制打开技能。这接受重新安装同名技能仍受原用户选择约束的行为，以免把文件生命周期错误地当成名称设置的独占所有权。

Q12 确认 CLI 缺失或不兼容时保留可读定义、暂停写入，技能能力与已有市场／插件／Hook 能力分别验证。2026-10-17，用户在 Q13 确认完整共同理解，本决策已接受，功能随后按用户指令实现。技能写入仅开放给隔离验证过的 2.1.302；原市场／插件／Hooks 的 2.1.300 限制不变。实验确认独立技能设置键使用目录名，frontmatter 展示名另行呈现；旧命令使用冒号限定名。来源、版本限制及名称／别名验证见[事实核查](../../.scratch/claude-skills-management/RESEARCH.md)，访谈见[需求文档](../../.scratch/claude-skills-management/PRD.md)。

实现与验证记录见 [VERIFICATION.md](../../.scratch/claude-skills-management/VERIFICATION.md)。原始来源、名称调用设置与安装副本分别维护；外部文件变化、来源身份或名称歧义不会被预览确认绕过。
