# Qoder 两版分别作为独立来源，一条记录包含转写与配套目录

Qoder 国际版与国内版 CLI 是独立产品：二进制、账号与数据根各不相同，会话持久化布局相同。两者各自只解析到一个 home，因此按 [ADR-0008](0008-session-records-use-resolved-homes.md) 的边界分别登记为独立来源「Qoder」与「Qoder CN」，而不是同一个来源下的版本维度。

Qoder 每条会话由一个转写文件与同名配套目录（本地状态、子代理对话）共同构成；只有配套目录而没有转写的剩余数据仍按会话记录处理。CLI 运行诊断日志记录的是运行过程而非对话，体积远大于转写，不属于会话记录。移除把一条记录的转写与配套目录一起移入废纸篓，并沿用 [ADR-0023](0023-session-record-operations-share-lifecycle-not-policy.md) 的共享生命周期。

与 Grok Build 不同，Qoder 不设来源级退出要求：会话是普通文件，继续会话按标识精确读取，未发现需要静默期的共享索引；移除只做文件级「使用中」检查。

## Considered Options

- 一个来源下分两个版本：违反 ADR-0008 一个来源只解析一个 home 的契约；两版可同时安装，扫描状态、年龄门槛与维护记录都需要各自的归属。
- 只以转写文件为记录、把配套目录留在原处：会留下含子代理对话的不可见数据，移除后也会留下孤儿目录，与 Grok Build 以目录作为记录边界的先例不一致。
- 把诊断日志纳入记录：会扭曲记录大小，并显著扩大一条记录对应的移除范围。
- 要求 Qoder CLI 退出后才允许移除：Qoder 未表现出 Grok 式的共享索引依赖，整源门槛会无故阻止可安全执行的移除。
- 调用 Qoder CLI 的原生删除：不满足 [ADR-0005](0005-session-record-removal-uses-trash.md) 的废纸篓恢复语义。

## Consequences

- 两个来源各自观察、各自计数、各自记录维护历史；只安装一版时，另一来源呈未找到状态。
- 记录大小包含转写与配套目录；记录离开原目录不等于已经释放物理空间。
- 有配套目录而无转写的记录以「未命名会话」呈现，允许明确选择和按年龄移除；使用中的记录保留。
- 按年龄移除依据记录内的最后活动时间，缺失时回退配套目录状态或文件修改时间；无法确定活动时间的记录不参与按年龄移除，仍可明确选中。
- 子代理对话随所属记录整体移除，不单独列出，也不级联影响其他记录。
- 配套目录须为普通目录，不跟随符号链接，保持 [ADR-0009](0009-symlinks-are-not-session-records.md) 的边界；Grok Build 已有的目录例外不变。
- 诊断日志不属于记录边界，也不在本操作范围内。
