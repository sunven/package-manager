# Codex 钩子定义从用户来源文件读取并原位维护

原生清单在 Hooks 总开关关闭时不能枚举定义，且不提供结构化编辑所需的完整原始内容。为支持关闭时仍可维护配置，本轮选择读取当前 Codex home 的用户定义文件作为配置编辑对象，以原生清单提供启用与信任状态；不从文件存在推断当前会话已加载或获得信任。这扩展了 ADR-0013 的用户定义读取与写入范围，插件定义继续只读，项目定义不纳入管理。

JSON 与内联 TOML 的已有定义在原文件维护，新建沿用已有单一来源，首次默认 JSON，双来源并存时由用户明确选择；不把自动迁移或重建整份配置作为编辑前提。信任审查继续交给 Codex。

本机实验发现按位置变化的原生身份可能让未编辑条目继承其他条目的启用和信任记录。因此定义维护必须同时保护其他条目的定义与启用选择，身份变化者重新审查，不迁移旧信任；无法可靠保护时拒绝操作。仅覆盖定义文件不足以满足此边界，JSON 与状态文件的保存也不能宣称跨文件事务。该取舍接受部分操作需要额外审查，避免将身份变化误当成用户对另一条 Hook 的授权。

来源与总开关行为已由本轮 Q2、Q5–Q7 确认，状态保护取舍由 Q11 确认，完整方案由 Q12 确认。此记录为已接受的设计，产品接入尚待实现；见[需求文档](../../.scratch/codex-hooks-configuration/PRD.md)与[事实核查](../../.scratch/codex-hooks-configuration/RESEARCH.md)。
