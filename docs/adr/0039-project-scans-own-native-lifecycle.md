# 项目派生数据扫描在 Rust 中拥有完整生命周期

前端停止项目派生数据扫描时只停止测量调度并丢弃迟到结果，原生发现和已开始的测量仍继续；前端还在原生工作结束前声明终态、写入项目扫描记录并允许修改预设。决定由 Rust 的项目扫描 module 统一拥有发现、最多四路测量、协作停止、扫描会话更新和终态记录写入，通过一次运行命令、按轮次匹配的停止命令和进度通道提供 interface。这取代 ADR-0032 中由前端驱动扫描与测量的安排；项目清理批次保持独立。

## Considered Options

- 只补原生停止标志，保留前端终态与记录编排：能减少文件遍历，但停止时间、记录归属和预设移除仍跨越多个调用。否决。
- 停止时立即解锁，后续忽略原生结果：会继续允许旧工作与新扫描重叠，并使记录写入晚于所属预设移除。否决。
- Rust 拥有扫描生命周期，前端展示进度与终态回执：采纳。

## Consequences

- 开始时冻结预设身份和已授权的扫描根目录、深度；扫描会话与候选 ID 继续由 Rust 签发，清理不接受任意路径。ADR-0003 继续有效。
- 原生登记轮次后立即发送开始进度。前端在此之前收到的停止请求会保留，取得轮次 ID 后再发送，避免启动时丢失停止请求。
- 发现和测量在目录及条目之间检查停止标志。中断测量不产生完整或部分占用结果，候选保持未测量；清理前后的测量与资格复核不接受扫描停止标志。
- 请求停止后，页面显示正在停止；原生遍历、已开始的测量和终态记录写入尝试结束后，才允许重扫、修改预设或开始清理。单个已开始的文件系统调用与有超时限制的工具探测仍需返回。
- 测量期间仍允许选择和清理已完成测量且符合资格的候选。进度与终态更新保留用户选择和并行清理结果；不以初始扫描快照覆盖它们。
- ADR-0029 的记录归属、完整性、比较基线、保留限额和损坏保护继续有效。发现阶段停止不产生扫描会话或记录；测量阶段停止保存完整发现范围及停止状态。记录候选集合来自发现，不因期间的清理而改写。
- 终态时间和记录由 Rust 产生，一轮只写一次；写入失败只随回执返回警告。视图失去连接不终止原生记录编排。前端不再提交扫描记录草稿或调度逐候选测量。
