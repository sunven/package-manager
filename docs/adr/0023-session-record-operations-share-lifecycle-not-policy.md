# 会话记录操作共享生命周期机制，不共享资格策略

会话记录移除与 OpenCode 会话永久删除各自拥有资格规则、删除计划和执行命令，但共享确认快照、执行锁、读取作废、结果保留与后续读取的顺序。共享机制集中在一个操作模块中，策略留在各自的 adapter；共享模块不自行判断可移除性、批量范围或是否需要刷新。这样生命周期竞态只修一处，同时避免把可恢复的废纸篓移除与不可恢复的永久删除合并成通用删除策略。

## Considered Options

- 让两个 hook 各自维护完整生命周期：每修一次竞态都要改两处，测试也要重复验证同一组规则。否决。
- 把所有资格规则合并成一个通用删除策略：会抹掉废纸篓、使用中检查、OpenCode 级联与预检之间的差异。否决。
- 只共享确认、执行锁、读取作废、结果保留和后续读取，资格与执行留给 adapter：采纳。

## Consequences

- 确认、读取作废、执行锁和刷新顺序的修改只落在共享模块。
- 资格、批量范围、完成 ID 与是否刷新的修改落在对应 adapter。
- ADR-0005、ADR-0007、ADR-0010、ADR-0021、ADR-0022 继续有效。
- 新增会话来源时实现一个 adapter，而不是复制一份 hook 生命周期。
- 模块测试覆盖生命周期，hook 与页面测试覆盖各自策略。
