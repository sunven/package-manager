# OpenCode 会话记录使用已登记的服务

OpenCode 的 SQLite 文件是整个会话库，直接操作会绕过其版本迁移、WAL 与父子会话语义；普通 CLI 命令还可能启动或替换后台服务。会话元数据因此通过 OpenCode 已登记且健康的本地服务只读分页读取。继续会话时先复核会话仍存在并取得其工作目录，再由 `opencode attach --dir <directory> --session <id>` 连接已发现服务；认证信息只传入短暂的受限启动脚本，不写入命令行参数或持久数据。

单条及明确选择的批量永久删除通过同一个已登记服务的官方 `DELETE /api/session/{id}` 接口执行。删除前先复核记录仍存在，并读取 `/api/session/active`；活动会话或状态接口不可用时，均阻止删除。服务端若返回冲突，则不报告成功；官方接口未承诺检查与删除原子执行，不能保证检查之后的活动变化一定被服务端阻止。OpenCode 会连同该会话的子会话一起删除，因此确认框展示所选记录及已读取的级联后代，明确说明不可恢复，也不将其称为移入废纸篓。应用不直接修改 SQLite。

批量删除时后端重读全局会话元数据，先核对每个明确选中的目标仍存在，再计算最新级联范围并去重实际删除的根会话。全部目标及后代预检通过后才开始按序删除；任一预检失败则整批不开始。执行中的首个失败会停止后续删除，逐项报告成功、失败及未执行，已成功项无法回滚。结果不确定时只刷新核对，不自动重复删除。

按 7／30 天永久删除使用同一服务边界；确认门槛与级联范围的复核规则见 [ADR-0022](0022-opencode-age-deletion-preserves-recent-descendants.md)。

## Considered Options

- 直接读取 SQLite：否决，因为数据库是整库存储且需跟随 OpenCode 的 schema/WAL 实现。
- 运行 `opencode --session`：否决，因为 CLI 可能自行启动、替换或连接其他后台服务。
- 手动配置服务 URL：否决，因为已登记服务发现能自动提供本地 URL 与凭据，减少端口猜测及凭据设置。
- 直接修改 SQLite 删除会话：否决，因为这会绕过 OpenCode 的数据模型与父子会话处理；使用已登记服务的删除接口。
- 允许删除正在运行的会话：否决，因为这可能中断当前对话；删除前由服务端复核活动状态，确认框提示先结束会话。

## Consequences

- OpenCode 未运行或未登记时，本工具不读取或删除记录，也不启动服务。
- 前端只收到会话元数据；服务密码不进入扫描响应、日志或 CLI 参数。
- 删除由 OpenCode 服务处理并会影响子会话；继续操作不创建分支或解除归档。
- 批量删除失败和未执行项保留选择；再次删除需要重新确认。刷新失败单独报告，不改变已经确认的执行结果。
