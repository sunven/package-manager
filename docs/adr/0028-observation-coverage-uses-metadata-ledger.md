# 观察覆盖度使用元数据台账，不持久化扫描内容

观察覆盖度需要跨重启展示 25 个观察项的最近成功观察、最近尝试、完整性和已知失效，但现有数据只给管理器和环境诊断提供了时间戳，项目扫描、VS Code、会话和代理扩展的读取状态只在内存中。决定由 Rust 拥有一个 `app_data_dir()/observation-ledger.json` 元数据台账，每个观察项只保留最新一条记录，分别保存成功与尝试各自的时间、范围、完整性和原因；前端把实时状态与台账合并成覆盖度视图。台账不保存包清单、扫描结果、会话内容、技能定义或文件内容，不提供观察历史，也不使用固定小时或天数阈值判断过期。目录不存在、清单不支持、功能开关关闭等结果是已观察的事实，不是未观察或失败；只有台账、没有当前内存结果时显示「上次观察」，而不是「已观察」。显式失效只跟随来源已有的依赖变化，不新增跨领域失效规则；管理器维护和项目清理不额外标记失效。范围变化只使用无需读取来源就能确定的当前范围描述（项目设置、PATH 与配置路径），管理器与 OpenCode 的范围由下一次读取结果更新。

## Considered Options

- 从现有管理器历史快照推导：只能覆盖管理器，项目、VS Code、会话和扩展仍然没有一致的新近度。否决。
- 持久化完整的扫描结果：会让应用复制来源数据，增加隐私、体积和过期副本问题，也会与来源页的实时状态冲突。否决。
- 使用 localStorage 保存观察元数据：不受 Rust 的原子写入与损坏保护约束，WebView 存储清理后丢失，且与现有历史存储不一致。否决。
- 使用统一的过期阈值：较早的观察不一定错误，固定小时或天数会把时间当成有效性判断。否决。
- 维护操作后统一标记相关观察失效：跨领域共享失效规则会抹平各来源已有的失效语义，与 ADR-0027 的结论冲突。否决。

## Consequences

- 新增台账文件、读取/写入命令与范围描述命令；每个来源在读取完成或显式失效时接入记录。
- 未来新增观察来源必须注册稳定 ID、提供范围描述，并在读取完成时写台账，否则只会显示为未观察。
- 覆盖度页打开时不调用任何命令，也不触发来源读取；它只使用应用启动时加载的本地台账与范围描述，以及已加载的内存状态。
- 台账损坏、未来版本或写入失败分别提示；写入失败不改变观察或维护结果，台账也不提供导出、清空或手动编辑。
- 管理器与 OpenCode 无法在不读取的情况下确定当前范围，因此不会主动显示「范围已变化」；下次读取会更新范围。
- 「上次观察」与「已观察」的区分贯穿徽章、计数和概览摘要，避免把元数据说成当前已加载的数据。
