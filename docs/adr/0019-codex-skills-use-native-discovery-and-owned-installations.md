# Codex 技能采用原生清单，应用维护自己持有的安装副本

技能管理需要完成查看、启停、安装、更新与卸载，但已核实的 Codex 接口只提供原生技能发现和启停，没有与插件生命周期对等的通用独立技能维护命令。设计访谈 Q5–Q7 已确认：清单及启停接入 Codex 原生接口并要求兼容 CLI；本应用维护独立技能的安装副本与来源记录，而不引入第三方技能管理 CLI。来源记录服务于维护资格及更新，不替代 Codex 识别技能的事实。

同一份技能可能通过共享目录或符号链接供多个代理使用。已有共享或外部链接技能仅支持查看及 Codex 启停，文件维护交回原来源；插件附带和内置技能只读。本应用为自己独立安装的技能提供完整维护，不因为技能出现在 Codex 清单中就认领其来源文件。Q8–Q11 进一步确认：新安装在当前 Codex home 的 `skills` 中保存副本，本地导入使用复制；旧技能不接管，包括位于该目录但没有本应用安装记录的普通技能。这接受部分既有技能不能在此更新或卸载的边界，以免把 Codex 配置维护扩大为其他工具的内容维护。

技能安装副本存在本地修改时停止更新，不合并或强制覆盖；卸载将整份副本移入废纸篓，保留原始来源。更新保留启停选择，并遵循已记录的分支或固定版本，不继承插件重新安装会启用插件的语义。它是用户资产维护，不扩展既有缓存或项目派生数据的永久清理边界。

Q15 接受原生清单的发现范围：不另外补读禁用插件的技能声明。这些声明继续在插件详情查看，不将声明存在当作原生已发现；本机 0.163.0 的隔离实验已验证持久禁用插件后其技能不再出现在清单中，但这不是跨版本枚举保证。

这一方案扩展独立技能能力，不改变 ADR-0014 的插件生命周期委托边界。2026-10-17，用户在 Q16 确认完整共同理解，本决策已接受，现已实现；见[需求文档](../../.scratch/codex-skills-management/PRD.md)与[事实核查](../../.scratch/codex-skills-management/RESEARCH.md)。

实现采用短期 app-server 的 `skills/list` 与 `skills/config/write`；安装先在临时 Codex home 中交给原生解析器验证，再发布独立副本。来源、目录身份与内容基准保存在当前 home 的 `.package-manager-skills.json`，不读取其他工具的锁文件授予维护资格。Git 使用裸仓库与归档取出内容，不检出或执行技能脚本；更新保留路径启停设置，卸载复用废纸篓机制。文件、记录与配置分别反馈结果，不承诺跨文件事务。验证边界见[验证记录](../../.scratch/codex-skills-management/VERIFICATION.md)。
