# 项目清理只接受扫描会话候选

项目派生数据路径来自用户选择的扫描根目录，无法像管理器缓存清理一样完全写入静态表；但若扫描或清理接口直接接受前端提交的路径，WebView 就能表达对任意本机项目目录的清理。我们决定由后端唤起原生目录选择器并登记授权根目录，前端只持有不透明的根目录 ID；后端再为每轮项目派生数据扫描创建会话并保存 Rust `target` 与 Node `node_modules` 候选，前端清理时只能提交扫描会话 ID 与候选 ID。重扫使旧会话失效，执行前后端仍按候选类型重新验证项目标识、目录身份及扫描根目录边界；Node 依赖目录的额外删除护栏见 [ADR-0004](./0004-node-dependency-directories-use-guarded-deletion.md)。

## Consequences

- 后端需要维护已授权根目录、当前扫描会话及候选映射，扫描与清理接口因此是有状态的。
- 上次选择的扫描根目录与深度由后端持久化；应用重启后由后端恢复路径并签发新的根目录 ID，而不是让前端回传路径重新授权。
- 不能为了简化 IPC 而改成接受前端提交的任意路径或完整 Cargo 参数；这会扩大 WebView 的清理权限面。
