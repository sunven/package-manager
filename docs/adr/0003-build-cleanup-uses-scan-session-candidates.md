# 构建目录清理只接受扫描会话候选

构建目录路径来自用户选择的扫描根目录，无法像管理器缓存清理一样完全写入静态表；但若扫描或清理接口直接接受前端提交的路径，WebView 就能表达对任意本机 Rust 项目的清理。我们决定由后端唤起原生目录选择器并登记授权根目录，前端只持有不透明的根目录 ID；后端再为每轮扫描创建会话并保存候选，前端清理时只能提交扫描会话 ID 与候选 ID。重扫使旧会话失效，执行前后端仍重新验证 `Cargo.toml`、非符号链接的同级 `target` 及其扫描根目录边界。

## Consequences

- 后端需要维护已授权根目录、当前扫描会话及候选映射，扫描与清理接口因此是有状态的。
- 上次选择的根目录与扫描深度由后端持久化；应用重启后由后端恢复路径并签发新的根目录 ID，而不是让前端回传路径重新授权。
- 不能为了简化 IPC 而改成接受前端提交的任意路径或完整 Cargo 参数；这会扩大 WebView 的清理权限面。
