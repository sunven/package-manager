# 会话记录目录测量按每次扫描重新计算

Qoder 配套目录内已有文件增长、后代文件增删时，目录自身的 inode 与 mtime 可以不变；Grok 的浅层指纹同样不能覆盖附件和深层子代理元数据。因此跨次扫描复用目录测量结果会保留旧占用、关联记录或读取完整性。决定删除这两套缓存，由 Qoder 与 Grok 各自的记录测量 module 在每次扫描中重新遍历目录，不再向调用方暴露目录缓存的锁和容器。

## Considered Options

- 递归验证缓存：检测后代变化仍需遍历目录，还要核对关联元数据和读取失败状态；没有测量证据支持额外的复用机制，暂不采用。
- 用短期有效期复用：有效期内仍会把旧结果作为新观察返回，不能解决刷新后的有效性问题，不采用。
- 每次重新测量：复用现有来源内的遍历实现，移除命中和淘汰规则，采纳。

## Consequences

- 重复扫描增加文件系统遍历，大量记录的刷新可能变慢；转写增量解析、进程与打开文件的现有缓存继续保留。
- Qoder 两版仍是独立来源，记录范围遵守 ADR-0034；Grok 保持 ADR-0030 的独立目录策略。各自的遍历限额、不跟随符号链接、完整性表达和序列化格式保持原有规则，不引入通用目录缓存 interface。
- 遍历陈述本次读到的文件系统事实，不承诺并发写入期间的原子快照。扫描结果仍不代替移除时的身份、活动时间、使用中或运行状态复核。
