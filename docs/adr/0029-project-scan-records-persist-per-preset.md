# 项目扫描记录按预设独立持久化并冻结变化

项目派生数据扫描已经支持保存扫描根目录预设，但预设只保存路径和深度，用户无法确认某个预设最近是否扫描过、扫描覆盖了多少项目，以及自上次可用扫描以来候选发生了什么变化。观察台账按 ADR-0028 只保存最近一次观察的元数据，不提供观察历史，也不保存扫描内容；管理器快照和维护历史都不覆盖项目扫描。决定由 Rust 在 `app_data_dir()/project-scan-history.json` 中维护独立的项目扫描记录，带 schema 版本并原子写入。每条记录由扫描根目录预设拥有，只在扫描产生会话时写入（正常完成，或用户在测量阶段取消），记录完成/停止时间、path+depth、发现完整度（跳过目录数）、测量阶段状态（结束或用户取消）、发现项目数（总数及 Rust/Node/Maven 分解）、候选数（总数及类型分解），以及相对比较基线的候选变化；不保存测量值、候选状态或错误详情，也不记录单项目测量失败。扫描结果为此新增按项目标记识别的发现项目计数。比较基线是同一预设、同一 path+depth 下最近一次发现完整的扫描；候选身份使用 `kind + directoryPath`，因为 `candidateId` 只在单轮扫描内有效。变化和基线计数在写入时冻结；基线候选键集合按 `(preset, path, depth)` 单独持久化，并与记录在同一次原子写入中更新。发现不完整的扫描不更新基线，也不产生变化比较。每个预设保留最近 20 条记录（含不完整扫描），移除预设时同时删除其记录和基线。记录写入失败不改变扫描与清理结果，只显示警告；记录文件损坏或版本过新时停止写入，不覆盖。历史记录只读，不授权清理，不链接维护历史，不回溯填充已有预设，也不提供单独的“已审阅”状态。`project-scan` 的观察范围键同时从 `rootId + path + depth` 改为 `path + depth`，因为 rootId 每次启动都会变化。

## Considered Options

- 写入观察台账：台账按 ADR-0028 明确不保存扫描内容、不提供观察历史，会破坏其元数据边界。否决。
- 每条记录保存完整候选快照：能事后重算任意基线，但会复制扫描内容，增加隐私与体积，也超出“少量历史信息”的目标。否决。
- 按 path+depth 而不是预设归属：预设删除后记录仍可见，但失去用户实际使用的复核单位，也让“移除预设”留下不可见数据。否决。
- 只和紧邻的上一条扫描比较：中间出现发现不完整的扫描时会长期没有变化可看。否决。
- 从管理器快照或维护历史重建项目扫描变化：两者都不包含项目扫描的项目与候选集合。否决。
- 使用 localStorage：不受 Rust 原子写入与损坏保护约束，与现有历史存储不一致。否决。

## Consequences

- 应用会在观察台账之外保存有限的扫描内容：项目/候选计数、新增/消失候选路径，以及每个预设每个深度的最近基线候选键集合。记录随预设删除，最多 20 条/预设；基线在预设存在期间按深度保留（深度 0–32 最多 33 份）。
- 差异在写入时冻结。后续扫描器规则或比较规则变化不会改写旧记录；用户也不能事后选择其他基线重算。
- 扫描在终态前崩溃或退出不会留下记录；记录写入失败时，观察台账仍可能显示该扫描已观察，两者按各自职责独立。
- 发现不完整时项目数和候选数只是下限，界面必须显示跳过目录数与“未比较”。
- 移除预设会丢失其扫描记录；重新添加同一路径会得到新的预设身份并从空记录开始。
- `project-scan` 的观察范围键变化后，升级后首次扫描前覆盖度可能出现一次“范围变化”。
- 项目扫描记录不参与清理授权；清理仍只依据当前扫描会话，遵守 ADR-0003。
