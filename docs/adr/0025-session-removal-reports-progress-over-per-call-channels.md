# 批量会话记录移除通过每次调用独立的 Channel 报告进度

批量会话记录移除在确认后的执行阶段向前端报告进度：命令先报告预检，再报告执行时重新确定的候选总数，之后每处理完一条记录报告一次累计计数。进度只属于这一次调用，因此使用 Tauri 的每次调用 Channel，而不是全局事件；进度状态由共享的会话记录操作生命周期持有，单条移除与 OpenCode 永久删除仍是一次性结果。

## Considered Options

- 前端逐条调用现有单条移除命令：能天然获得进度，但按年龄移除会失去执行时对最后活动时间与使用状态的整源复核（ADR-0007），并为每条记录重复 lsof。否决。
- 使用全局 Tauri 事件并以前端操作 id 关联：需要额外的命名、订阅清理与串话防护，和一次确认对应一次执行调用的既有模型不一致。否决。
- 只显示不确定的粗粒度阶段：不需要后端改动，但无法回答用户最关心的“还剩多少”。否决。
- 每次调用携带 Channel，Rust 在逐条循环中推送累计计数：采纳。

## Consequences

- 这是仓库第一处流式 IPC；批量移除命令多一个 Channel 参数，其他一次性命令不受影响。
- 进度分母是执行时重新确定的候选集合，可能不同于确认时的条数；界面同时显示已移入、跳过和失败。
- 预检阶段没有总数，显示不确定状态；候选为零时不显示进度条，直接进入既有结果提示。
- 执行结束后迟到的进度消息必须被忽略；进度随操作生命周期一起清空。
- 单条记录失败不中断循环，进度继续。
