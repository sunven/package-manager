# 跨领域维护历史共用记录外壳，不共用资格与恢复边界

维护历史统一记录管理器维护、项目清理、VS Code 工作区存储移除和会话记录操作。一次用户确认对应一条记录，批次内的每个操作目标产生独立子结果；记录共用外壳（领域、操作、确认范围、执行摘要、后续读取或核对），但每个领域保留自己的确认范围、状态原因、恢复边界和空间口径。记录由 Rust 在真实执行点写入，前端不能写入任意目标结果；历史写入失败只提示，不改变操作结果。旧的管理器维护记录迁移到新文档并保留原文件；全局保留最近 500 条已关闭记录，执行中的记录不因上限被淘汰，应用重启后仍未关闭的记录标记为已中断。

## Considered Options

- 各领域独立维护历史文件：每增加一个领域都要重复保留、迁移和读取规则，用户也没有一个入口回看跨领域操作。否决。
- 把所有领域压成通用删除记录：会抹平废纸篓移除、永久删除、级联删除、护栏删除和委托清理之间的差异。否决。
- 前端通过通用命令写入历史：实现简单，但 WebView 可以伪造历史，应用崩溃时也拿不到执行点的逐目标事实。否决。
- 共用记录外壳、保留领域负载、由 Rust 写入：采纳。

## Consequences

- ADR-0026 中「VS Code 移除不新增维护记录」的结论被取代；VS Code 工作区存储移除写入维护历史，页面不再声称不记录。
- ADR-0023 继续有效：会话记录操作共享生命周期，不共享资格策略。
- 管理器操作记录从 `manager-history/maintenance.json` 迁移到 `manager-history/maintenance-v2.json`；快照文件与每管理器 20 份限额不变，原文件保留作备份。
- 后续读取与核对分别记录；项目清理没有后续读取，清理调用内的重新测量属于执行结果。
- 按年龄的会话移除只冻结规则与门槛，执行时目标总数另记；OpenCode 的实际完成集合与冻结计划不一致时必须在历史中可见。
- 代理扩展维护仍不在维护历史范围内。
- 全局保留最近 500 条已关闭记录，不提供清空、导出或手动置顶。
- 维护历史只读，不构成撤销、备份或维护授权。
